AI 供应商合同带来传统技术合同没有的风险：供应商会不会用客户数据训练模型、模型变更时客户能否得到通知、AI 产出侵权内容谁担责、供应商是否完成了法定的算法备案和安全评估（《生成式人工智能服务管理办法》第17条〔待核〕）。本指引用于系统审查这些 AI 特有风险。

## 适用情形

审查 AI SaaS 协议、AI 模型授权、AI API 服务条款，或采购团队询问某份 AI 供应商合同有没有问题。

管辖法律、争议解决、保密等通用合同要素按供应商协议审查办理，本指引只看 AI 特有风险。

## 需要准备的材料

- 供应商合同条款（含服务条款、数据处理协议、SLA）。
- 公司的合同审查立场、可接受风险阈值、红线条款。
- 适用的法规框架。
- 已批准的供应商名单及其通过审查的条款。

## 办理步骤

### 第1步：服务定性

| 提供方式 | 说明 | 关键风险 |
|-------------|------|----------|
| API 接口 | 通过云端 API 调用模型 | 数据传输安全、数据是否被记录用于训练 |
| 本地部署 | 模型部署在自有服务器 | 安全可控性高，但更新和升级依赖供应商 |
| SaaS 产品 | 使用供应商的 AI 功能产品 | 使用条款可能不清晰，数据用途条款需特别关注 |
| 模型授权/定制 | 授权基础模型进行微调 | 知识产权归属、模型更新的兼容性 |

### 第2步：训练数据（最重要的部分）

核心问题：
1. 供应商是否使用客户数据训练模型？
2. 如果是，客户是否知情并同意？
3. 训练数据中是否包含个人信息或敏感个人信息？
4. 客户数据流出后能否追回（「遗忘」在操作上是否可行）？

| 检查项 | 理想状态 | 风险标记 |
|--------|----------|----------|
| 训练数据条款 | 明确约定不将客户数据用于模型训练，或经客户明确书面同意 | 🔴 合同沉默，或笼统声称供应商可「使用数据进行服务改进」 |
| 个人信息训练 | 不将含个人信息的数据用于训练，或已取得个人单独同意（《个人信息保护法》第23条） | 🔴 不区分数据类型，一刀切授权 |
| 训练数据合法性保证 | 供应商保证训练数据来源合法，不侵犯第三方知识产权（《生成式人工智能服务管理办法》第7条） | 🟠 仅「尽力」保证或不提供保证 |
| 数据删除 | 合同终止后删除客户数据并销毁包含客户数据的模型副本 | 🟠 仅承诺「停止使用」而不承诺删除 |
| 知识产权归属 | 明确约定微调模型的权属（客户拥有/供应商拥有/共享） | 🟠 合同沉默 |

训练数据红线：
- 供应商单方保留「为改进服务目的」使用客户全部数据的权利，且不可协商。
- 供应商拒绝就训练数据的合法来源提供任何保证。
- 涉及个人信息，供应商却拒绝签署数据处理协议（参照《个人信息保护法》第21条）。

### 第3步：责任分配

| 责任场景 | 理想立场 | 风险 |
|----------|---------------|------|
| AI 产出侵权（知识产权） | 供应商承担因其训练数据或模型本身导致的侵权责任 | 🔴 全部侵权风险转嫁客户 |
| AI 产出违法/不良内容 | 供应商依《生成式人工智能服务管理办法》承担内容安全责任 | 🔴 供应商声称仅为「技术中立工具」 |
| AI 产出错误导致商业损失 | 责任分配合理，特殊或间接损失合理排除 | 🟠 供应商完全免责，客户承担全部损失 |
| 模型停机/服务中断 | SLA 明确，有可用性承诺和服务积分/赔偿机制 | 🟡 SLA 模糊或缺失 |
| 模型性能退化 | 供应商保证模型输出质量不实质性下降 | 🟠 供应商保留单方修改模型的权利且无通知义务 |

《生成式人工智能服务管理办法》第9条要求提供者承担生成内容的生产者责任。供应商声称自己只提供「技术工具」、不对 AI 产出负责的，这一立场在法规层面的支撑较弱；但实践中供应商可能通过合同把部分风险转给使用者，需逐案分析。

### 第4步：模型变更通知

- 供应商能否单方修改模型（通常可以，关键在通知和影响评估）？
- 变更需提前多久通知（行业惯例 30-90 天）？
- 变更实质性降低性能或合规性的，客户有无终止权？
- 供应商停止支持某个模型版本的，有无合理的退出安排？

| 检查项 | 最低可接受标准 |
|--------|--------------|
| 实质性变更通知 | 至少30天提前书面通知 |
| 性能退化补救 | 变更导致性能退化超过【X】%的，供应商在合理期限内补救 |
| 终止权 | 供应商无法补救或变更影响合规状态的，客户有权终止 |
| 合规影响评估 | 变更前提供合规影响摘要（至少概要说明） |

### 第5步：合规义务传导

作为 AI 服务使用者，须确认供应商有能力支持公司的合规义务：

| 合规要求 | 供应商应尽的义务 | 合同核查点 |
|-------------|-----------------|-----------|
| 算法备案（《互联网信息服务算法推荐管理规定》第24条） | 已完成备案并提供备案号 | 合同是否明确算法备案状态？有无持续合规保证？ |
| 安全评估（《生成式人工智能服务管理办法》第17条〔待核〕） | 已进行安全评估 | 能否获取评估结论摘要（不要求完整报告，但需确认已完成） |
| 科技伦理审查（《科技伦理审查办法（试行）》） | 已完成伦理审查（如适用） | 是否涉及需伦理审查的场景？ |
| 个人信息保护（《个人信息保护法》） | 涉及数据处理的，签署数据处理协议 | 数据处理协议是否充分 |
| 安全措施（《个人信息保护法》第51条） | 承诺采取必要的安全措施 | SOC2/等保报告、安全事件通知时限、数据泄露通知义务 |
| 审计权 | 接受审计或提供第三方审计报告 | 审计权的范围和频率 |
| 内容安全 | 具备违法和不良信息识别和处置机制 | 信息安全管理能力描述或认证 |

供应商的备案承诺须自行核实：通过网信办公开渠道或供应商提供的备案号查验。

### 第6步：汇总并出具意见

风险汇总表：

| 类别 | 法律风险 | 商业摩擦 | 关键风险点 |
|------|----------|----------|-----------|
| 训练数据 | 🔴🟠🟡⚪ | 🔴🟠🟡⚪ | 【要点】 |
| 责任分配 | 🔴🟠🟡⚪ | 🔴🟠🟡⚪ | 【要点】 |
| 模型变更 | 🔴🟠🟡⚪ | 🔴🟠🟡⚪ | 【要点】 |
| 合规传导 | 🔴🟠🟡⚪ | 🔴🟠🟡⚪ | 【要点】 |

总体结论分三档：经核准 / 附条件核准 / 不适合当前条款。触发红线的条款交法律顾问决定。本审查是法律和合规审查，不评估模型的技术性能。
