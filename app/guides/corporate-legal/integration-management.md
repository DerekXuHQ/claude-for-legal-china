---

外部律师把交易交割完，接下来的整合工作落在法务身上。本篇管理的是交割后的**法律**工作：同意事项、合同转让、主体合理化、知识产权登记、收购协议项下的义务，跟踪哪些已完成、哪些将到期、哪些受阻、哪些需要决策。业务整合、IT 系统、人力组织设计不在范围内，法务只跟踪其中需要法律意见的节点。

## 适用情形

- 并购交易已交割，需要推进交割后的同意、转让、登记和协议义务；
- 需要定期向交易负责人、企业发展部门或董事会报告整合进度。

## 需要准备的材料

完整的收购协议能生成最完整的计划；材料不全也可以先搭框架，逐步补充。

| 已有材料 | 能得到什么 |
|---|---|
| 完整收购协议 | 完整工作计划 + 带截止日的必需同意清单 + 协议关键日期 |
| 收购协议 + 合同清单 | 上述内容 + 合同转让分级清单 |
| 交易摘要、条款清单或外部律师的交割后待办清单 | 标准工作计划框架，必需同意先用占位符 |
| 都没有 | 标准第1/30/90/180天工作计划框架，由律师补充同意事项和合同清单 |

另外准备：交易基本信息（交易代号、目标公司、交割日、交易负责人、外部律所和牵头律师）、交割检查表中标为交割后的事项、合同清单。

## 办理步骤

### 1. 从收购协议提取关键内容

- **必需同意清单**：每项同意的对方当事人、合同类型、协议约定的截止日。
- **交割后义务**：逐项转为工作计划事项，按截止日归入相应阶段，注明依据为“收购协议义务”。
- **关键日期**：
  - 必需同意的截止日；
  - 陈述与保证的存续期——一般陈述、基本陈述、税务陈述通常期限不同，按协议分别提取记录，不假设默认值；
  - 托管释放日期；
  - 业绩对赌的考核日和付款日（负责人一律记为财务部门，法务只跟踪日期）。
- 交割检查表中标为交割后的事项，转入第1天或第30天计划，沿用其状态。

### 2. 建立分阶段工作计划

每个事项记录：编号、描述、阶段、法务负责或法务支持、所属工作流（法务 / 人力 / 信息技术 / 财务 / 不动产 / 其他）、优先级（关键 / 高 / 中 / 低）、截止日、截止日依据（收购协议义务 / 监管要求 / 最佳实践）、状态（未开始 / 进行中 / 已完成 / 受阻 / 推迟）、受阻原因、前置事项、备注。

标准事项如下，再加上从协议提取的义务：

**第1天（交割后7天内）**

| 法务负责 | 优先级 |
|---|---|
| 被收购主体更名的，办理名称变更登记 | 关键 |
| 更新银行账户签字人，向银行提交交割文件 | 关键 |
| 工商登记变更 | 高 |
| 交割时推迟办理的关键知识产权转让，完成签署 | 关键 |
| 域名和社交媒体账号转移 | 高 |
| 董事及高管责任保险：确认被收购主体董事的延长报告期保单已生效 | 关键 |
| 按注册地要求向市场监督管理部门办理股东变更手续 | 高 |

法务支持：员工公告和沟通（人力负责，法务审阅，关键）；福利在首日的延续（人力负责，法务就劳动法问题提供意见）；客户沟通函（业务负责，法务审核准确性）。

**第30天**

| 法务负责 | 优先级 |
|---|---|
| 必需同意首轮推进：联系所有对方当事人并记录 | 关键 |
| 专利、商标转让在国家知识产权局办理登记 | 高 |
| 著作权转让备案 | 中 |
| 商标转让登记 | 高 |
| 完成第1级、第2级合同的转让分析 | 高 |
| 保险延长报告期保单最终确认 | 高 |

法务支持：数据迁移的个人信息保护审查（IT 负责，法务就数据传输机制提供意见）；不动产租赁合同转让条款审查（行政/设施负责）。

**第90天**

| 法务负责 | 优先级 |
|---|---|
| 必需同意截止：全部取得或已上报（截止日按协议） | 关键 |
| 主体合理化决策：保留独立 / 合并 / 注销的建议 | 高 |
| 福利计划承继或终止的文件 | 高 |
| 第二轮同意推进：剩余未决同意 | 高 |
| 第3级（控制权变更条款）合同处理完毕 | 关键 |

法务支持：人力资源制度统一（人力负责，法务就劳动法提供意见）。

**第180天**

| 法务负责 | 优先级 |
|---|---|
| 决定合并的，办理合并登记 | 高 |
| 决定清理的，办理注销登记 | 高 |
| 需要以收购方名义重签的合同全面换签 | 高 |
| 陈述与保证存续期跟踪：记录即将到期的日期 | 中 |

### 3. 合同转让分级

合同清单可以来自交割后仍可访问的合同库或数据室、合同管理系统导出或手工清单，或收购协议披露清单中的重大合同清单（最低限度，转让条款需人工审查）。清单至少要有合同名称和对方当事人；有合同类型、年度金额、转让条款原文更好。

逐份判断转让机制：

| 机制 | 含义 | 级别 |
|---|---|---|
| 需经同意 | 明确禁止未经对方同意转让 | 1 或 2 |
| 含控制权变更条款 | 对方因交易取得终止权或同意权 | 3 |
| 自动转让 | 无限制，或明确允许转让给关联方、承继方 | 4 |
| 未约定 | 无转让条款，适用管辖法律的默认规则；查明该规则并引用具体规定，交律师审查 | 2 |
| 未审查 | 未能读取或找到转让条款 | 交人工审查 |

列入收购协议必需同意清单的合同，无论机制如何，一律为第1级。

| 级别 | 含义 | 处理 |
|---|---|---|
| 第1级 必需同意 | 列入协议清单，有硬截止日 | 必须取得同意 |
| 第2级 重大且需同意 | 有转让限制，未列入协议清单 | 建议第90天前取得 |
| 第3级 控制权变更条款 ⚠️ | 对方因交割取得终止权或同意权 | **立即联系对方**，单独醒目列示——终止权可能已在交割日触发并在计算期限 |
| 第4级 自动转让 | 无需联系 | 仅跟踪 |

初始状态：第4级为“无需行动”，第3级为“控制权变更已触发”，第1、2级为“等待同意”，未审查的为“未审查”。

每份合同记录：编号、名称、对方当事人、合同类型、年度金额、转让机制、级别、是否必需同意、协议截止日、状态（未审查 / 无需行动 / 等待同意 / 已发函 / 谈判中 / 已取得同意 / 已完成转让 / 已豁免 / 被拒绝 / 控制权变更已触发）、经办人、备注、最近更新日。

同意事项记录：编号、对方当事人、合同类型、是否列入协议必需同意清单、协议截止日、状态（未开始 / 已发函 / 谈判中 / 已取得 / 已豁免 / 被拒绝）、经办人、发函日期、取得日期、备注。

### 4. 更新状态

- 按律师告知的变化更新相应事项，并联动更新下游状态（例如第1级同意全部取得后，相应协议义务标为已满足）。
- 收到外部律师或各工作流负责人的状态文件，按对方当事人名称或事项描述匹配更新；匹配不上的，可能是需要新增的事项，单独列出。
- 同意被拒绝的，标记为“收购协议义务可能未满足”，建议请外部律师判断是否构成赔偿请求的基础。

### 5. 定期状态报告

见下方模板。

### 6. 导出

可按工作计划、同意、合同分别或合并导出，供外部律师、企业发展部门或董事会使用。导出电子表格时，以 `=`、`+`、`-`、`@` 或制表符、换行符开头的外来文本前加单引号，CSV 中的逗号、双引号、换行符按规范转义，防止被当作公式执行。

## 模板：整合状态报告

报告来源于收购协议、尽调发现和交割后整合记录，继承其保密状态；向保密范围以外分发可能丧失保护，发送前确认收件人。

```
整合状态 — 【交易代号】 / 【目标公司】
【日期】 — 交割后第【N】天

执行摘要
【2–3句：整体状态、最大风险、自上次报告以来的关键进展】

必需同意  【截止日：日期 — 剩余【N】天】
  已取得：  【N】/【总数】（【%】）
  谈判中：  【N】
  已发函：  【N】
  未开始：  【N】
  被拒绝：  【N】 ⚠️

⚠️ 有风险：【对方当事人】 — 【N】天后截止，发函无回应
⚠️ 被拒绝：【对方当事人】 — 收购协议义务未满足，上报外部律师

合同转让
  第1级（必需同意）：      已完成【N】 / 进行中【N】 / 待处理【N】
  第2级（重大合同）：      已完成【N】 / 进行中【N】 / 待处理【N】
  第3级（控制权变更条款）： 已解决【N】 / 未决【N】 ⚠️
  第4级（自动转让）：      【N】 — 无需行动

工作计划 — 法务负责
  🔴 逾期（【N】）：【事项】 — 应于【日期】完成
  ⏰ 本周到期（【N】）：【事项】 — 【日期】到期
  ✅ 自上次报告以来完成（【N】）：【事项】 — 【日期】完成

受阻事项和待决策事项
  【事项】 — 受阻于：【原因】 — 负责人：【姓名】
  【事项】 — 需要决策：【内容】 — 建议：【选项】

即将到来的关键日期
  【日期】 — 【里程碑 / 截止日】
  【日期】 — 陈述与保证存续期届满 — 确认无待处理的赔偿请求
```

## 注意事项

- 业务整合（IT、人力、财务、不动产）由业务部门负责，法务只跟踪需要法律意见的节点。
- 同意请求函、合同换签协议另行起草或由外部律师出具。
- 同意被拒或截止日错过时，只做标记；赔偿请求或违约后果的法律分析由律师负责。
- 业绩对赌的达成情况由财务部门负责，台账只记录考核日和付款日。
- 报告依据台账中律师更新的状态，不在报告时重新审阅合同。
