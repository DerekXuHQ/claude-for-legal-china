数据室里可能有2000份文件，真正对交易重要的大约30份。本篇说明如何按尽调类别和重要性阈值审阅数据室文件、提取问题，并按内部格式写出发现，再把需要交割前完成的事项交给交割检查表。

## 适用情形

- 审查数据室或其中某个文件夹；
- 尽调中需要从文件中提取问题、形成问题清单。

## 需要准备的材料

- 团队的尽调类别、重要性阈值和问题备忘录格式（最好有一份既往备忘录作范本）；
- 本交易的特定阈值和数据室位置；
- 数据室索引。

## 办理步骤

### 1. 盘点数据室

把数据室文件夹对应到尽调资料清单的各类别，标出缺口：资料清单中有、数据室中没有对应内容的类别，需要发补充请求。

```markdown
## 数据室盘点：【交易代号】

| 资料清单类别 | 数据室文件夹 | 文件数 | 状态 |
|---|---|---|---|
| 公司及组织 | /01-公司文件 | 【N】 | 已审查 |
| 重大合同 | /02-合同 | 【N】 | 进行中 |
| 知识产权 | /03-知识产权 | 【N】 | 未开始 |

**缺口：**【无数据室内容的类别——需发补充请求】
```

某类别文件量很大（例如超过50份同类合同）且团队有批量审查工具的，先按批量条款提取指引外包，本流程处理补充协议、修订协议等需要细读的文件。

### 2. 适用重要性阈值

按阈值审阅，例如阈值为“合同金额大于¥【X】”的，不必审全部合同。合同按标明金额（文件名或元数据中有的）或对方当事人重要性排序，自上而下审，直到低于阈值或该类别审完。

### 3. 按类别提取问题

| 类别 | 标准关注点 |
|---|---|
| 重大合同 | 控制权变更条款（是否被本次交易触发、是否需对方同意）；合同转让限制（能否转给买方）；独家/竞业限制（是否限制买方业务）；最惠国待遇（价格约束）；解除权（对方是否会因交易取得解除权）；异常的赔偿或责任承担 |
| 公司 | 股权结构是否准确、未行权期权/认股权；交易所需的董事会批准；股东协议限制（领售权、随售权、优先购买权）；子公司结构和关联安排 |
| 知识产权 | 权利归属链条（创始人、员工的转让是否到位）；产品中的开源代码（传染性许可风险）；关键知识产权是许可还是自有；未决或可能发生的知识产权诉讼 |
| 劳动 | 控制权变更触发的离职补偿安排；关键员工留任风险；未决劳动争议；用工性质风险（名为承揽、实为劳动关系） |
| 诉讼 | 未决案件和计提准备；可能发生的索赔；监管调查；系列性、群体性案件 |

此外标出可能随交易转移的责任：未决或可能发生的侵权、产品责任索赔，环境事项和治理义务，卖方在资产转让后是否保留足以清偿其他债权人的资产，卖方交割后是否计划清算，以及收购协议中承担/排除责任的清单是否真正覆盖已知风险。

### 4. 写出每项发现

按团队范本格式写，范本用项目符号就用项目符号。常见格式：

```
问题 #【N】：【标题】
类别：【资料清单类别】
严重程度：【按内部分级】
文件：【数据室路径 + 文件名】
发现：【文件说了什么，为什么重要】
建议：【价格调整 / 赔偿 / 需取得同意 / 陈述与保证 / 退出】
```

**严重程度**（团队采用红黄绿分级的）：

- 🔴 **红色**：影响交易价值或结构。例如需要主要客户同意的控制权变更、未披露的重大诉讼、知识产权归属缺口。
- 🟡 **黄色**：需要关注，可以解决。例如需要同意但大概率能取得、需要整改的开源代码、用工性质风险。
- 🟢 **绿色**：记录备查，与陈述与保证一致，除陈述与保证外无需行动。

**引用法律时的要求：**

- 注明每项法律依据的出处（法律数据库检索、官方网站、交易团队或外部律师提供等）；凭记忆写出、未经核实的，句末标〔待核〕，优先核查。数据室文件的路径、页码、文件名照原样保留。
- 交易对方、卖方披露文件或团队笔记引用某法条支持其主张，而办理人认为不对，又暂时拿不到条文原文的，不要自行描述该条内容，写明“该条文与预期不符，需调取原文判断”，然后调取原文、请提供方提供原文，或交外部律师判断。对真实法条自信而错误的描述，比“不清楚”危害更大。
- 检索结果不足以支撑某项发现的法律依据时，如实报告检索到的内容，不用网络搜索或记忆悄悄补齐。是否扩大检索、换数据库、采用较低可信度的来源（采用的须标明并对照官方来源核实），或标为未核实并停止，由律师决定。

### 5. 按类别汇总

按资料清单类别分组，类别内按严重程度排序（见下方模板）。

大类别（例如300份合同）分批处理。每批结束后更新问题清单，发现红色问题立即上报，不等整个类别审完。问题超过约10条的，可以做成看板：按严重程度和类别计数，附可排序的问题明细表。

### 6. 交接

- 汇总发现进入交易团队简报；
- 合同层面的提取结果进入重大合同披露清单；
- **凡意味着交割前需完成某项行动的发现，都交给交割检查表**，不限于第三方同意：
  - 股东会/董事会行动：必需的股东同意、董事会决议，或交割需要的其他公司批准。写明行动、批准门槛、法定或章程依据、时间限制；
  - 监管申报和审批：经营者集中申报、外商投资安全审查、行业主管部门审批；
  - 对方当事人同意：控制权变更、禁止转让、最惠国待遇触发的同意；
  - 解除、终止或清偿：与控制权变更挂钩的劳动关系解除、清偿函、担保物权解除；
  - 托管/扣留安排：与特定问题挂钩的赔偿托管或扣留款。
- 处于灰色地带（可能是交割前行动，也可能是交割后承诺）的，加标记后照样交接。漏交难以发现，多交可以在审查时剔除。

## 模板：类别问题汇总

汇总来源于受保密义务或律师工作成果保护的数据室材料，继承其保密状态；向保密范围以外分发可能丧失保护，应存放于事项的保密文件中，审慎决定分发。

```markdown
# 尽调问题：【交易代号】 — 【类别】

**已审文件：**本类别【M】份中的【N】份
**覆盖：**【全部 | 超过¥【X】阈值 | 前【N】份】
**发现：**【N】🔴 【N】🟡 【N】🟢

---

### 结论

【🔴 N 阻断 · 🟠 N 高 · 🟡 N 中】 — 【交易团队需要知道的一件事】

---

【逐项发现，按内部格式】

---

## 缺口

- 【无文件回应的资料清单项目】
- 【被引用但不在数据室中的文件】
```

## 注意事项

- 临界情形的重要性由人判断，本流程只按阈值筛选。
- 发现用于为谈判提供信息，陈述与保证的谈判另行进行。
- 收尾时由律师决定下一步：起草文件、上报、补充事实、等待观察或其他。
