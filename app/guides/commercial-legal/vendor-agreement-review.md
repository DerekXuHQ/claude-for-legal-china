用于对照团队实际使用的审查指引审查对方提供的供应商主协议、服务协议等，找出每项偏离条款，并写明每项怎么处理——给出具体修订语言，而不是笼统的「可考虑修改」。成果是律师一次就能据以操作的审查备忘录。

## 需要准备的材料

- 协议全文及订单、数据处理协议等附件。
- 团队审查指引：标准立场、曾接受的让步、绝不接受的内容、审批权限、需要最先检查的交易底线。没有审查指引的，可以按通用默认（中国法管辖、中等风险偏好、无审查指引）先行审查，并在成果上注明「临时模式」。
- 本合同中公司处于哪一方。对方提供产品或服务的，本公司是采购方；对方购买本公司产品的，本公司是销售方。本指引通常用于采购方合同，但方向仍须确认；该方向尚无审查指引的，先完成配置。

## 办理步骤

1. **通读定位。**

   | 问题 | 答案 |
   |---|---|
   | 协议类型 | 主协议 / SaaS 订阅 / 专业服务 / 许可 / 其他 |
   | 我方角色 | 客户 / 供应商 |
   | 对方当事人 | 名称；大型企业（通常不谈判）还是初创企业（会谈判） |
   | 金额 | 年度/总合同价值 |
   | 期限 | 期限长度、续约机制 |
   | 数据处理协议 | 附带 / 通过网址引用 / 缺失 |
   | 订单 | 单独文件或集成在内 |

   - **金额缺失时停下来。** 主协议通常不载明金额，价格在订单里。没有年度合同价值就无法确定审批路由，可以：补充订单金额；确认高于还是低于审批阈值；或保守地交更高一级审批人。
   - **数据处理协议通过网址引用的**，注明数据保护分析不完整，建议另行单独审查数据处理协议。
2. **先查交易底线。** 存在审查指引中的交易底线条款的，在备忘录最前面写明（模板见下文），后续详细审查仅为完整性提供。
3. **逐条对比。** 对审查指引的每个类别找到对应的合同条款，每项偏离写明：审查指引立场、合同原文、差距类型、两个维度的风险等级、为何重要、建议修订语言、对方不让步时的方案。
4. **审查责任上限**（四个维度，见审查要点）。
5. **核对法域可执行性。** 审查指引立场与合同管辖法律下的可执行性冲突的，标注并注明「法域 — 需核实」。
6. **列出有利条款和缺失条款。**
   - 优于我方标准的条款：标出来，需要在别处让步时可作为交换筹码。
   - 完全缺失的标准条款：合同转让限制、审计权、不可抗力、保险要求等。
7. **确定审批路由。** 用上报矩阵对照合同金额、严重问题和自动上报事项，写明谁需要批准。
8. **组装备忘录。** 加工作成果页眉，仅在保密范围内分发。发送对象在保密范围外的（公共频道、全公司列表、对方当事人或其律师、供应商、客户），另备去标识化版本。
9. **发出修订前把关。** 发给对方的每处修订都会被视为我方谈判立场，属于法律行为。使用者不是律师的，须先经律师审阅；需要找律师的，可联系中华全国律师协会或当地律师协会。
10. **签署。** 协议可签署时，可在电子签约平台按正确顺序安排签署人；未经明确指示，不发出签署。

## 审查要点

### 差距类型与风险等级

差距类型：缺失条款 / 弱于标准 / 弱于让步 / 非标准结构 / 不可接受。

| 法律风险 | 含义 |
|---|---|
| 🔴严重 | 未解决前不要签署。审查指引「绝不接受」清单上的条款或交易底线 |
| 🟠高 | 强力推动驳回。超出审查指引让步范围的条款 |
| 🟡中 | 首轮推动驳回；如果是最后一项未决事项可接受 |
| 🟢低 | 注明即可。审查指引明确容忍的条款或纯粹措辞性偏离 |

商业摩擦：🔴阻碍交易 / 🟠减缓交易 / 🟡困扰客户 / 🟢不可见。

### 责任上限

上限金额是责任上限中最不重要的部分。逐一明确四个维度：

1. **直接损失与间接/附带损失**，分别说明处理方式。
2. **上限基数，逐字引用。** 「12个月上限」可能对应多种不同计算方式，相差可达一个数量级。
3. **上限与例外事项的关系。** 列明哪些在上限之外（例外事项）、哪些实际受上限约束，评估受约束的范围是否有意义。
4. **审查指引在每个维度上的立场。** 审查指引只有一个「标准立场」的，建议拆分为直接损失、间接损失、例外事项、基数四项。

### 中国法下的可执行性

- 《民法典》第506条明确无效的免责条款（造成人身损害、故意或重大过失造成财产损失）。
- 合同赔偿责任根据《民法典》第584条（可预见规则）和第591条（减损规则）确定。
- 格式条款受《民法典》第496-498条规制。
- 竞业限制主要适用于劳动合同关系（《劳动合同法》第23-24条）。

### 修订粒度

默认选择能达到审查指引立场的最小改动：换一个词优先于换一个短语，换一个短语优先于换一句话。有疑问时，选更小的。

### 来源要求

检索结果很少时，如实说明查到的情况，不用未经核实的网络资料或记忆补空白；是否接受较低可信度的来源，由律师决定。引用法规、规章或案例时注明出处。

## 检查清单

- [ ] 已对照审查指引并注明出处
- [ ] 已首先检查交易底线
- [ ] 每个问题都附具体替代语言
- [ ] 风险等级已校准
- [ ] 审批人已具名
- [ ] 已考虑对方当事人背景

## 模板

### 交易底线提示

```markdown
## ⛔ 存在交易底线问题

**第【X.X】条** 包含【交易底线事项】。根据团队审查指引，这是硬性拒绝。建议：

- [ ] 驳回——提出具体替代语言
- [ ] 退出——对方不让步则不签

以下详细审查仅为完整性提供，此项未解决前没有实际意义。
```

### 单项偏离

```markdown
### 第【X.X】条：【问题名称】

**审查指引立场：** 【我方标准立场】

**合同原文：**
> "【精确引用】"

**差距：** 【缺失条款 | 弱于标准 | 弱于让步 | 非标准结构 | 不可接受】

**法律风险：** 🔴严重 | 🟠高 | 🟡中 | 🟢低
**商业摩擦：** 🔴阻碍交易 | 🟠减缓交易 | 🟡困扰客户 | 🟢不可见

**为何重要：** 【一两句：条款保持现状会对业务产生什么不利后果】

**建议修订：**
> "【可直接粘贴到修订稿的替代语言】"

**对方不让步时：** 【让步方案，或「上报给【人名】」】
```
