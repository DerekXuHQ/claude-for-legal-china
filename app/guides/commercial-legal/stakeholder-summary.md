要签合同的业务负责人不想看法律备忘录。他们想知道：能签吗？有什么坑？需要我做什么？本指引用于把已完成的审查备忘录压缩成这样的回答，发给法务以外的人。

## 适用情形

- 供应商协议、SaaS 订阅协议等审查完成后，需要向业务部门、采购、财务、IT 等说明结论。

## 需要准备的材料

- 完成的审查备忘录（并注明当时按销售方还是采购方审查指引审查）。
- 摘要的阅读对象。不清楚的，先问清楚给谁看。
- 发送渠道。发送对象在保密范围外的，准备去标识化的版本。

## 办理步骤

1. **延续审查方向。** 采购方摘要讲「我们能得到什么、同意放弃什么」；销售方摘要讲「我们卖的是什么、需要承担什么义务」。
2. **按受众取舍内容。**

   | 受众 | 关心 | 不关心 |
   |---|---|---|
   | 采购 | 价格、续约机制、审批路由 | 责任上限结构 |
   | 部门负责人（预算持有人） | 团队能否使用、坏了怎么办、成本 | 赔偿范围 |
   | 财务 | 总持有成本、续约价格风险 | 管辖法律 |
   | 安全/IT | 数据处理、再处理者、安全认证、数据存放在哪里 | 其他一切 |
   | 发起高管 | 会不会让公司难堪、法务是否卡住 | 细节 |

3. **把法律发现翻译成业务语言**（见下文对照表）。
4. **控制篇幅后发送。** 通过审查指引指定的渠道发送。

## 篇幅与格式要求

- 一段：结论，以及这份合同在业务上是什么。
- 一段：需要注意的地方。
- 2-3 项清单：业务方实际需要做的事。
- 一行：审批人和预期时间。
- **总计不超过 200 字。** 超了，说明放进了业务方不需要的细节。
- 审查干净的，就直接写「没问题，可以签」，不要为了显得详尽写成三段。

**不写进摘要的：** 条款编号；带引号的定义术语；「赔偿」一词（改说「他们兜底」）；「尽管有」；带颜色圆点的风险矩阵；「本摘要不构成法律意见」之类的保留说明。

**语气。** 业务方记住法务的两件事：有没有卡住我、有没有讲清楚。写得像在茶水间向一位聪明的同事解释一样。

## 法律语言对照

| 法律发现 | 业务说法 |
|---|---|
| 「责任上限为12个月费用」 | 「如果他们出问题，我们最多能追回一年付给他们的钱。」 |
| 「无任意解除权」 | 「一旦签了，整个期限内都被锁定——不好用也不能直接取消。」 |
| 「60天通知自动续约」 | 「每年自动续约。要取消，须在续约日前两个月通知他们。」 |
| 「无知识产权赔偿」 | 「如果有人告我们这个工具侵犯了他们的专利，供应商不兜底。」 |
| 「未披露再处理者名单」 | 「我们不知道还有哪些公司会通过他们接触到我们的数据。」 |
| 「终止后30天内数据删除」 | 「取消后他们一个月内删除数据，之前要把需要的内容导出来。」 |
| 「SLA积分上限为月费10%」 | 「服务宕机了我们只能拿到一点积分，远远抵不上宕机对业务的损失。」 |

## 模板

```markdown
【工作成果页眉】

**【对方当事人】【协议类型】** — 【可以签字 | 需要变更 | 受阻】

【一段：这份协议在业务上是什么。不写「提供基于云的分析平台主服务协议」，而写「这是市场团队想用的那个数据看板工具的合同。」】

【一段：业务方需要知道的事。例如「注意：每年自动续约，必须在到期60天前取消。已加入续约追踪，但你需要知道。」或「干净的协议，没有意外，可以签字。」】

**需要你做的：**
- [ ] 【事项】

**审批：** 【审批人及预期时间】
```
