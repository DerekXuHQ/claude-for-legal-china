在做任何 PIA 之前，先要回答：这件事到底需不需要评估？需要的话，是什么类型，阻碍在哪里？分诊比 PIA 快，位于其上游——它不写评估报告，只确定是否需要评估以及需要满足哪些条件，深度工作交给 PIA。

分诊结论为以下四种之一：

| 分类 | 含义 |
|---|---|
| 🟢 **可直接推进** | 无需影响评估，适用标准保障措施 |
| 🟡 **需影响评估** | 部署前或同步开展评估 |
| 🟠 **法定评估强制触发** | 触发《个人信息保护法》第55条等法定评估义务（引用法条原文）；门槛更高，个人信息保护负责人或法务负责人可能需要介入 |
| 🔴 **停止** | 与个人信息处理规则冲突或缺乏合法性基础，重新设计后才能推进 |

## 适用情形

- 新的个人信息处理活动、产品功能或供应商关系，需要从隐私角度把关。
- 判断某项活动是否需要做 PIA。
- 一次性审视功能清单、产品路线图或待办列表（批量分诊）。

处理活动、处理者或受影响的个人属于中国大陆以外法域的，评估触发条件和合法性基础可能不同，须单独识别。

## 需要准备的材料

- 团队 PIA 内部触发标准、适用的监管制度范围、公司个人信息处理规则承诺——这三项是分诊的权威依据，通用的隐私法推理不能代替公司实际作出的承诺。
- 活动描述（越具体越好）。

尚未整理上述内部材料的，可先按通用默认值分诊：中国法域（个保法 + 数据安全法 + 网络安全法）、中等风险偏好、无内部谈判立场，按通用隐私法原则分类而不比对具体承诺；但须在结论中注明「按通用默认假设分诊，未比对公司内部标准和处理规则承诺」。

## 办理步骤

### 1. 理解活动

「新功能」「数据处理活动」这样的描述不足以准确分诊。描述模糊的，先问清楚：

- 收集或处理哪些数据？哪些类别？
- 个人信息主体是谁——客户、员工、第三方？
- 目的是什么？解决什么问题？
- 是新收集数据，还是重新利用已有数据？
- 有没有第三方供应商参与？新供应商还是已有供应商？
- 是否涉及自动化决策——结果会影响到人吗？
- 部署场景——仅内部、面向客户、公开？

### 2. 检查内部触发标准

满足团队内部 PIA 触发标准的，至少为**需影响评估**。

不满足的，继续第 3 步再下结论——有些活动不管内部政策如何都需要评估。

### 3. 法定评估检查

**先问行业监管叠加。** 活动触及受特别监管的数据类别的，行业监管往往是主导框架，应尽早识别，而不是事后补充。

本处理活动是否涉及：

- **金融账户数据或消费者的个人金融信息**（《个人金融信息保护技术规范》JR/T 0171-2020、《征信业管理条例》——适用于金融机构及其非关联第三方，对金融信息共享施加实体性限制）？
- **医疗机构或健康医疗数据处理者持有的健康医疗数据**（《人口健康信息管理办法（试行）》、个保法、健康医疗大数据管理相关规定——对使用和披露施加实体性限制，涉及病历数据、健康档案等）？
- **学校或为学校提供服务的教育信息化服务提供者处理的教育相关个人信息**（个保法知情同意要求，结合教育领域相关规定）？
- **面向未成年人或实际知晓未成年人使用其服务的运营者收集的不满十四周岁未成年人个人信息**（《儿童个人信息网络保护规定》、个保法第31条——监护人知情同意、通知义务、严格的保留和共享限制）？
- **其他行业制度**（如《汽车数据安全管理若干规定（试行）》规定的汽车数据处理、《征信业管理条例》规定的征信数据、《关键信息基础设施安全保护条例》规定的关键信息基础设施数据等）？

任一项为「是」的：行业监管通常提供主导性的实体限制，不只是个保法的豁免问题。先检索并引用具体规定，再继续。

**再查法定评估触发条件。** 对每个适用法域检索现行有效的法定评估触发条件，引用现行有效的法律、行政法规、部门规章或网信办指引并写明条号。国家标准和部门规章更新频繁，不能依赖静态清单；不确定的标出来交律师核实，不猜测。

《个人信息保护法》第55条法定评估触发情形（四类 + 兜底）：

1. **处理敏感个人信息**（第28条定义：一旦泄露或者非法使用，容易导致自然人的人格尊严受到侵害或者人身、财产安全受到危害的个人信息，包括生物识别、宗教信仰、特定身份、医疗健康、金融账户、行踪轨迹等信息，以及不满十四周岁未成年人的个人信息）
2. **利用个人信息进行自动化决策**（第24条：利用个人信息进行自动化决策，应当保证决策的透明度和结果公平、公正，不得对个人在交易价格等交易条件上实行不合理的差别待遇）
3. **委托处理个人信息、向其他个人信息处理者提供个人信息、公开个人信息**（第21-23条、第25条）
4. **向境外提供个人信息**（第38-40条，以及《数据出境安全评估办法》《个人信息出境标准合同办法》）
5. **其他对个人权益有重大影响的个人信息处理活动**

任一适用制度的法定触发条件满足的，结论为**法定评估强制触发**，不论内部标准如何。

**强指标**（不一定触发法定义务，但强烈建议评估）：

- 新技术应用，或对现有技术的创新性使用
- 未成年人数据
- 合并原本分开收集的数据集
- 可能导致歧视的数据
- 个人信息主体不会预期的处理活动
- 跨场景行为广告或基于追踪的广告技术（面向消费者的公司常见，常引发处理规则承诺冲突和行业监管叠加）

有一个或多个强指标、但未检索到法定触发条件的，升为**需影响评估**，并在结论中注明「非法定强制」。

### 4. 个人信息处理规则冲突检查

逐项检查拟议活动是否与公司已声明的每项承诺一致。常见冲突：

- 处理规则写「我们收集 X、Y、Z」，本活动收集 W——先更新处理规则，或停止收集 W。
- 处理规则写「我们不会向第三方出售或共享数据」，本活动把数据交给供应商用于其自身目的——研究该流转在各适用制度下是否属于受监管的「提供」或「共享」。
- 处理规则规定了保留期限，本活动保留时间更长。
- 处理规则写「我们仅将数据用于【某目的】」，本活动未重新取得同意或评估合法性基础就用于新目的。
- 处理规则列明了提供的个人权利，本活动产生了现有权利流程覆盖不到的新数据类别。

存在直接冲突的，结论为**停止**——不是「谨慎推进」。必须先解决冲突（更新处理规则或重新设计活动）。

### 5. 分类并出具结论

按下文「文书结构」出具。结论为需影响评估或法定评估强制触发的，随即进入 PIA 编制，把活动描述和已识别的触发条件一并带过去。

### 6. 相关交接

只在确有意义时提出，不作模板化附加：

- **AI 治理**：活动涉及 AI 系统作出或影响关于个人的决策的，除 PIA 外可能还需算法安全评估和科技伦理审查，二者并行，不能相互替代。
- **产品法务**：属于产品上线一部分的，同步产品法务的上线审查。

## 边界情形

- **「数据已匿名化」不等于可直接推进。** 问清匿名化方式，以及在给定数据集下重新识别是否实际可行。假名化数据依据个保法仍为个人信息。
- **「我们已经在做类似的事」不能代替分诊。** 从未评估过的现有活动，不能为新活动提供「祖父条款」。新活动在规模、目的或数据类别上有实质差异的，重新分诊。
- **「只是试点」不能跳过分诊。** 涉及真实用户或员工数据的试点同样受触发条件约束；需要评估的，试点也要评估。
- **「供应商负责所有隐私事项」。** 供应商处理基础设施，公司仍是决定目的的个人信息处理者。个人信息流向供应商的，需要数据处理协议，分诊仍适用于目的。
- **推断数据和衍生属性也算。** 活动生成关于个人的推断数据（如行为评分、偏好预测）的，把推断属性当作个人信息分诊。「只是算个分数」不能掩盖分数代表的内容。

## 文书结构

### 单项分诊

```markdown
【工作成果标头】

### 结论
【需影响评估 / 法定评估强制触发 / 可直接推进 / 停止——一句话说明理由】

---

**活动描述：** 【对处理活动的理解】

**分类：** 【可直接推进 / 需影响评估 / 法定评估强制触发 / 停止】

**内部触发标准满足？** 【是 / 否】
**个保法第55条法定评估触发？** 【是——【触发情形】 / 否 / 不适用】
**个人信息处理规则冲突？** 【无 / 有——【具体冲突】】

**理由：**
【1-3句话。可直接推进：说明在现行处理规则下安全的理由。需影响评估 / 法定评估：说明产生义务的原因。停止：指出冲突的具体承诺或原则。】
```

结论为需影响评估或法定评估强制触发的，附推进前置条件：

| 要求 | 负责人 | 完成？ |
|---|---|---|
| 【如：个人信息保护影响评估——完整格式】 | 【隐私法务】 | ☐ |
| 【如：合法性基础评估（如需）】 | 【隐私法务】 | ☐ |
| 【如：咨询个人信息保护负责人（法定评估路径）】 | 【个人信息保护负责人】 | ☐ |
| 【如：供应商数据处理协议已签署】 | 【隐私 / 法务】 | ☐ |
| 【如：上线前更新个人信息处理规则】 | 【隐私法务】 | ☐ |
| 【如：同意机制已搭建并测试】 | 【产品】 | ☐ |
| 【如：个人信息主体权利流程覆盖新数据类别】 | 【隐私 / 产品】 | ☐ |

**合法性基础（个保法第13条）：** 【告知同意 / 合同必需 / 法定义务 / 人力资源管理 / 合理处理已公开信息 / 紧急情况 / 其他——或「尚不明确，需在影响评估中确定」】

结论为停止的，写明：

```markdown
**冲突：** 【冲突的具体处理规则承诺或原则】

**要推进，须改变以下之一：**
- 【选项A——重新设计活动以避免冲突】
- 【选项B——更新个人信息处理规则以覆盖该活动（同时审查更新本身是否符合合法性基础）】
```

没有可行路径的，不要硬给；活动根本无法与已声明承诺或合法性基础调和的，直接写明。

### 批量分诊

先出摘要表，再逐项展开非「可直接推进」的条目：

| # | 活动 | 分类 | 关键条件 / 阻碍 |
|---|---|---|---|
| 1 | 【活动】 | 🟢 可直接推进 | — |
| 2 | 【活动】 | 🟡 需影响评估 | 需合法性基础评估；供应商数据处理协议未到位 |
| 3 | 【活动】 | 🟠 法定评估强制触发 | 大规模敏感个人信息（个保法第55条第1项） |
| 4 | 【活动】 | 🔴 停止 | 个人信息处理规则冲突——目的限制 |

工作成果标头：律师出具的写「保密——律师工作成果——按照律师指示准备」；非律师出具的写「研究笔记——非法律意见——在行动前应由执业律师审阅」。完成后给出下一步选项：开始 PIA；升级报批；补充事实；暂缓观察；其他。

## 常见风险

- 描述太笼统就下结论。
- 只看内部标准，内部未触发就直接放行，漏掉法定触发。
- 忽视行业监管叠加。
- 处理规则冲突时给出「谨慎推进」而非「停止」。
- 以匿名化、类似既有做法、试点、供应商负责等理由跳过分诊。
- 忽视推断数据。
