本指引用于 App、网站、小程序、SaaS、管理端、SDK 等产品上线前，形成基础隐私合规文档。目标不是写一份大而全的深度协议，而是用尽量精简的正文加必要表格，把基础问题讲清楚：谁在处理个人信息、产品范围、收集哪些个人信息、有哪些第三方或 SDK、存在哪里、是否跨境、用户怎么行使权利、是否涉及 AI 或其他高风险处理；并交付清单与复查报告。

整体顺序：确认按最小合规版处理 → 采集产品事实 → 先校验核心缺口 → 基于已确认的事实生成正文与清单 → 复查并列出后续完善事项。

## 适用情形

- 产品上线前需要一份基础隐私政策（隐私协议）。
- 需要个人信息清单、第三方 / SDK 清单、跨境传输清单。

本指引只产出**最小合规版**。需要完整版、正式深度版或在最小版基础上继续扩充的，先交付基础协议、缺口清单和后续完善事项，深度版另行处理。

最小合规版不等于低标准版。缺少处理者身份、联系方式、产品范围、个人信息类型、用户权利路径、第三方或 SDK 状态等核心事实的，先列出阻断问题，不直接编写协议。

## 总原则

- **不捏造事实，不编造条文。** 必要事实不清楚的，向业务方询问，或列为阻断缺口，绝不臆造。
- **法条须核实。** 引用法律、行政法规、部门规章、国家标准、平台规则前，核对现行有效版本和条文号；拿不准的依据标注「需进一步核实」，不照搬可能过期或不存在的条款。
- **不覆盖既有内容。** 业务方已提供或填写的内容视为权威，不在原位替换、删除、改写、压缩或润色；只填明确为空或标为缺失的字段。既有内容有风险、矛盾、模糊或不合规的，写入复查报告，不悄悄改动正文。
- **区分必要与非必要个人信息**，按业务功能分别说明；有具体类型时不用「相关信息」之类模糊表述。
- **统一术语**：「个人信息处理者」「个人信息主体」「敏感个人信息」「委托处理」「对外提供」「跨境传输」「个人信息安全事件」等。

## 需要准备的材料

- 既有隐私政策（如有）、产品说明。
- 上线端或渠道（App / H5 / 网站 / 小程序 / SaaS / 管理端 / SDK / 开放平台）。
- 已有的个人信息清单、第三方清单、跨境说明、安全措施、用户权利渠道、AI 功能说明等。

从零起草的，按下面的核心事实逐项向业务方询问，缺一项问一项。

## 办理步骤

### 1. 采集产品事实

需要采集的核心事实：

1. **处理者身份**：个人信息处理者名称 / 主体类型、联系方式、个人信息保护负责人或投诉渠道。
2. **产品范围**：产品名称、形态（App / 网站 / 小程序 / SaaS / SDK 等）、目标用户、是否面向未成年人。
3. **业务功能**：核心功能与对应的个人信息处理目的，逐功能拆分。
4. **个人信息类型**：每项收集的字段、是否敏感个人信息、必要还是非必要、收集方式（用户填写 / 自动采集 / 第三方获取）。
5. **设备权限**（App / 小程序）：相机、麦克风、相册、定位、通讯录等的调用场景和触发时机。
6. **第三方与 SDK**：名称、目的、涉及的数据类型、处理方式、触发时机、合作方主体。
7. **存储与跨境**：存储地域、保存期限或期限确定方法、是否跨境传输及接收方。
8. **用户权利**：查阅、复制、更正、删除、撤回同意、注销账号、投诉的入口与响应方式。
9. **AI / 高风险事项**：是否涉及生成式 AI、模型训练、个性化推荐、自动化决策，用户输入是否用于训练等。
10. **更新机制**：协议更新如何通知用户。

参考同类产品隐私政策或竞品链接的，**只借鉴章节结构、清单字段、披露颗粒度和产品特定数据类别的覆盖思路**，不复制其表述、措辞、示例或格式。借鉴所得的建议放在单独的「同类产品参考建议」部分，除非明确要求写入正文。

### 2. 先校验再起草

起草前核对输入是否覆盖以下基本要求，有缺口先返回，不带病起草：

- 处理者身份与联系方式是否齐全；
- 各业务功能与处理目的是否一一对应；
- 个人信息类型是否区分必要 / 非必要，是否标出敏感个人信息；
- 第三方 / SDK 状态是否明确；
- 存储地域、保存期限、跨境情况是否清楚；
- 用户权利路径是否完整。

涉及下列情形的，加做专项检查并在复查报告中提示：敏感个人信息、未成年人个人信息、跨境传输、自动化决策、广告 / 个性化推荐、AI 训练、重要数据、关键信息基础设施、高监管行业。这些维度对照《个人信息保护法》《数据安全法》《网络安全法》的相关要求审视，所引条文一律核实，不凭记忆断言条文号和内容。

处理方式可能有误或高风险的（如超范围收集、强制授权、捆绑同意、敏感权限无场景调用等），写明具体问题、原因、修正方向和依据层级（区分法律依据 / 监管规则参考 / 国家标准参考），不只给笼统风险提示。

### 3. 起草正文与清单

按下文「协议骨架」组织正文，保持简短、清楚、可上线：

- 详细规则前加一段简明摘要；
- 个人信息收集、SDK / 插件、第三方提供、跨境传输、保存期限、用户权利渠道优先用表格表达（见下文清单）；
- 按产品形态补充渠道差异（App、小程序、SDK 各有不同披露重点；小程序应披露实际调用的接口 / 组件 / 插件及授权路径）；
- 每项非必要个人信息说明拒绝提供的影响；
- 每类主要个人信息说明保存期限或期限确定方法；
- 写明存储地域和是否跨境；
- AI 相关：说明用户输入 / 输出是否用于模型训练或优化、默认设置、授权与撤回路径、退出训练集的机制；不得把训练或数据再利用埋进笼统的「改进服务」条款。

### 4. 复查与后续完善

按下文「复查报告结构」输出，问题分级为阻断 / 高风险 / 一致性 / 表达 / 建议补充，并列出最小合规版未能展开、需要后续完善的事项。

## 审查要点

- 核心事实（处理者、联系方式、产品范围、个人信息类型、权利路径、第三方 / SDK 状态）是否齐全。
- 功能与目的是否对应，必要 / 非必要是否区分，敏感个人信息是否标出。
- 非必要信息是否写明拒绝的影响。
- 保存期限、存储地域、跨境情况是否写明。
- AI 训练用途是否单独、明确披露。
- 正文与清单是否一致；既有内容是否被擅自改动。
- 引用的法条、标准是否已核实现行版本和条文号。

## 常见风险

- 超范围收集、强制授权、捆绑同意。
- 敏感权限没有对应的调用场景。
- 用「相关信息」等模糊表述代替具体字段。
- 把模型训练或数据再利用埋进「改进服务」。
- SDK 清单与实际集成不符。
- 照搬竞品措辞。
- 引用记忆中已过期或不存在的条文。

## 模板

### 协议骨架（最小合规版）

```
《【产品名称】隐私政策》

一、摘要（用一段话说明：谁在处理您的个人信息、收集哪些、用途、是否对外提供、是否跨境、您有哪些权利）

二、我们是谁
- 个人信息处理者名称 / 主体
- 联系方式与个人信息保护投诉渠道

三、我们收集哪些个人信息、为什么收集
- 按业务功能列出（见「个人信息清单」）
- 区分必要 / 非必要；标出敏感个人信息
- 设备权限调用场景（如适用）

四、我们如何使用 Cookie 或同类技术（如适用）

五、我们如何对外提供、共享、转让、公开披露个人信息
- 第三方 / SDK（见「第三方 / SDK 清单」）
- 委托处理情形

六、个人信息的存储与跨境
- 存储地域
- 保存期限或期限确定方法
- 是否跨境及接收方（如适用）

七、我们如何保护个人信息
- 安全措施概述
- 个人信息安全事件的处置与通知

八、您的权利与行使方式
- 查阅、复制、更正、删除、撤回同意、注销账号
- 行使路径、身份验证、响应时限、拒绝理由、投诉渠道

九、未成年人个人信息（如适用）

十、AI / 自动化决策相关说明（如适用）
- 输入 / 输出是否用于模型训练或优化、授权与撤回机制

十一、本政策如何更新
- 更新通知方式

十二、如何联系我们
```

### 个人信息清单

| 业务功能 | 个人信息类型 / 字段 | 是否敏感 | 必要 / 非必要 | 收集方式 | 处理目的 | 保存期限 |
|---|---|---|---|---|---|---|
| 示例：账号注册 | 手机号 | 否 | 必要 | 用户填写 | 创建账号、登录验证 | 账号注销后【X】日内删除 |

（非必要项须在另一列或备注中写明「拒绝提供的影响」。）

### 第三方 / SDK 清单

| 名称 | 类型（SDK / 接口 / 合作方） | 合作方主体 | 涉及个人信息类型 | 目的 | 处理方式 | 触发时机 / 频次 | 是否跨境 |
|---|---|---|---|---|---|---|---|

### 跨境传输清单（如适用）

| 接收方 | 所在国家 / 地区 | 传输的个人信息类型 | 目的 | 合规路径（如标准合同 / 认证 / 评估等，须核实适用情形） |
|---|---|---|---|---|

### 复查报告结构

```
一、阻断问题（缺失即不能上线的核心事实 / 章节）
二、高风险问题（合规风险，需优先处理）
三、一致性问题（前后表述 / 清单与正文不一致）
四、表达问题（用户难理解、术语混用）
五、建议补充项（可上线，但建议完善）
六、后续完善事项（最小合规版未展开、需后续补做的内容）
七、依据提示（凡引用法条 / 标准，逐条提示核实现行有效版本与条文号）
```

### 随附说明

起草成果须随附以下说明，单独放置，不与对外发布的协议正文混排（明确要求写入正文的除外）：

> 本文档依据所提供的产品事实起草，仅供参考，不构成正式法律意见、合规结论、监管意见或平台审核保证。所引法律、法规、国家标准及条文号可能存在变动或偏差，须经核实。正式发布、提交审核、对外使用或用于监管沟通前，请咨询具备资质的律师或数据合规专业人士。
