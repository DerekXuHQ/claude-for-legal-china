个人信息主体权利请求（查阅、复制、删除、更正、解释说明等）有期限、有流程，环节多且容易出错。本指引逐步说明从收到请求到发出回复、留存记录的全过程。

## 适用情形

- 收到个人要求查阅、复制、删除、更正其个人信息，或注销账户、要求解释处理规则的请求。
- 组合请求，例如「先把数据发给我再删除账户」（按查阅 + 删除两个关联请求处理）。

本指引不包括：直接查询各业务系统（由经办人或技术人员按清单执行）；对边界情形的豁免作最终决定（由律师判断）；发送回复（起草、审核后由人发送）。

## 需要准备的材料

- 请求原文（邮件、表单、客服记录等）。请求含个人信息：确认存储和传输环境符合数据处理要求；删去不需要的内容（身份证附件、无关邮件）；文件名中不出现主体姓名。
- 公司内部的权利请求处理流程：
  - **系统清单**：用户数据所在的每一个位置。清单为空或过时的，先标出来——不知道数据在哪里，就无法完整处理请求。
  - 身份验证方式。
  - 内部回复时限（SLA）。
  - 常规请求和升级请求分别由谁处理。
- 升级路径。

## 办理步骤

### 1. 判断是否需要升级

出现以下情况之一的，先按升级路径报告，再继续处理：

- 请求人是（或可能是）原告、对方律师或记者。
- 请求范围异常（如「包括关于我的内部沟通在内的所有数据」）。
- 存在覆盖该个人数据的诉讼保全（删除请求与诉讼保全冲突，由律师决定）。
- 请求人对此前的权利请求回复有争议。
- 有监管机关被抄送或提及。

### 2. 分类请求

识别个人在行使哪项权利（《个人信息保护法》第44-50条）：

| 权利 | 法条 | 内容 |
|---|---|---|
| 查阅 | 第45条 | 获取其个人信息副本及处理相关信息 |
| 复制 | 第45条 | 获取其个人信息副本（可携带） |
| 删除 / 注销账户 | 第47条 | 删除其个人信息（受豁免条件限制） |
| 更正 | 第46条 | 修正不准确的数据 |
| 解释说明 | 第48条 | 要求解释说明个人信息处理规则 |
| 拒绝 / 限制 | 第44条 | 知情权、决定权框架下的限制处理 |

继续之前，对每项被行使的权利检索适用规则：识别适用法域和法律依据，引用现行有效的法律或行政法规，写明具体条号、权利范围和例外，注意生效日期。不确定的标出来交律师核实，不陈述未经确认的规则。检索结果很少或为零的，如实报告覆盖不足，由律师决定是否扩大检索或接受可信度较低的来源。具体款号、条号最容易出错，必须对照原文。

个人信息主体、处理活动或处理者位于中国大陆以外的，规则和期限可能不同，须单独识别，不能直接套用本指引。

### 3. 验证身份

按公司规定的验证方式，常见做法：

- **已登录验证**：请求来自已验证的登录会话，身份即已确认。
- **邮件匹配**：请求来自档案中登记的邮箱，对低风险请求通常足够。
- **额外验证**：高价值账户或删除请求，采用验证问题、电话核实、身份证件等。

**按风险校准。** 验证过度会让申请流程变成障碍，在监管机关面前不好看；验证不足则可能把他人的数据交给欺诈者。

身份无法验证时，回复：

```markdown
我们无法验证本请求发自相关个人信息主体本人。为继续处理，请【验证步骤】。在请求未经核实前，我们无法提供个人信息。
```

验证问题是否中止期限存在争议，不要拖延——几天内就告知需要验证，不要拖到期限将满。

### 4. 定位数据

逐个系统查询并记录：

| 系统 | 已查询？ | 查到数据？ | 什么数据 |
|---|---|---|---|
| 生产数据库 | | | |
| 数据分析平台 | | | |
| 客服工单系统 | | | |
| CRM | | | |
| 邮件营销 | | | |
| 日志 | | | |
| 备份 | | | （删除时通常豁免，见下文） |
| 受托处理者 / 第三方 | | | （删除时可能需要通知他们） |

公司是 B2B 受托处理者的：「个人信息主体」往往是客户的最终用户。先确认这是否应由客户（处理者）处理——许多 DPA 约定受托处理者应将权利请求转给处理者。

### 5. 豁免分析

并非所有数据都必须提供或删除。对每一项数据，检索适用制度下可能存在的豁免（如第三方隐私、法律特权、商业秘密、安全、法定保留义务、诉讼准备、备份循环安排），引用现行有效规定并写明条号。豁免范围因法域和制度而异，须核实时效，不确定的标出来。

**不凭主观判断缩小清单。** 有善意依据的豁免都先提出，不确定的标注出来，由律师在回复发出前缩小范围。放弃一项后来被认定适用的豁免代价很高——材料一旦披露，豁免实际上就没了；而多提一项合理的豁免，律师审核时可以纠正。

每项提议的豁免都注明：「提议——主张前须经律师审核。监管机关会审查一揽子豁免主张，清单由律师缩小。」

需要理清的常见问题：

- 记录中是否含有关于**其他人**的数据，提供前需删去？
- 是否有具体的法定保留义务阻止删除？写明依据。
- 是否有覆盖该个人数据的诉讼保全？
- 是否有需记录的备份循环或技术可行性安排？（不能当作一般性借口。）

**每项主张的豁免都要留档。** 监管机关问为什么没删除某项数据时，「我们有法定义务」需要写明出处。

### 6. 起草两份函件

多数制度期望（或要求）在实质回复之外有一份及时的确认函。分别起草两份，不要合成一份拖到期限最后一天才发。在最后一天发出的单一合并函件，即使内容正确，也是流程失败。

- **确认函**：收到请求后数日内发出（目标当日至3-5日内，始终远早于法定期限）。确认收到，复述对请求内容的理解，说明回复时限和目标日期，索要尚缺的身份验证材料。不作实质披露。及时的确认函是监管机关看到的第一个信号，表明流程在运转，也能降低重复请求或过早投诉的风险。
- **实质回复函**：实际的披露、删除确认或数据导出。在法定期限（或更严的内部时限）内发出，且只在身份验证完成、数据定位和豁免分析完成后发出。

两份函件都是对外文件，**不加**工作成果标头。附随的内部笔记、日志和豁免分析属于律师工作成果，单独保存并加标头；内部豁免分析中应写明引用来源的核实情况——所主张的豁免、回复期限和延期机制特别容易出错，向个人或监管机关主张任何豁免前必须核实。

**发送前把关。** 函件是供律师审核的草稿。发送意味着公司对某一立场负责，可能放弃豁免，也可能启动监管机关的时限计算。须经执业律师审核、修改和批准后方可发送。经办人不是律师的，提交律师时附一页摘要：个人信息主体；被行使的权利；适用制度；在各系统查到的数据；扣留了什么及依据哪项豁免；身份验证情况；回复期限；发函前应向律师确认的三件事。需要寻找执业律师的，可通过当地律师协会或司法局的律师查询系统。

### 7. 留存记录

权利请求会被审计。记录：收到日期、身份验证日期、回复日期、提供或删除了什么、主张的豁免及依据、处理人。有权利请求跟踪工具的在其中建档；没有的，用日志文件。

## 期限管理

- **两份函件规则**：确认函目标当日至3-5日内发出；实质回复函在法定期限前发出。
- **检索当前有效的回复期限**：针对被行使的具体权利和适用法域，查明是否有延期机制、可延多久、使用延期须向个人发出什么通知；查明期限从何时起算（收到、验证完成或其他——默认按收到起算，逐个制度核实）。引用现行有效规定并写明条号，注意生效日期，数据保护回复时限经常修订。
- **起算点**：回复期限自收到请求起算，而非自身份验证完成起算，除非适用制度另有规定。不要以验证为由默示中止期限；某制度有不同起算规则的，写明依据，不作假设。
- 内部时限比法定期限更严的，按内部时限执行，并注明法定底线。
- 需要延期的，在初始期限到来之前尽早发出「需要更多时间」的通知；最后一天才延期观感很差。

## 常见风险

- 系统清单不全，漏查数据所在位置。
- 验证过度构成障碍，或验证不足导致向他人泄露数据。
- 以验证未完成为由拖延，期限实际已在计算。
- 只发一份函件，拖到期限最后一天。
- 擅自放弃本可主张的豁免，或主张豁免却拿不出依据。
- 删除请求与诉讼保全冲突而未升级。
- B2B 场景下直接处理了本应转交客户处理的请求。
- 在对外函件上加了工作成果标头，或把内部豁免分析发给了个人。

## 模板

### 确认函

```markdown
主题：我们收到了您的个人信息请求 — 【公司】 — 【日期】

尊敬的【姓名】：

我们于【收到日期】收到了您的【查阅 / 删除 / 复制 / 更正】请求。

**按我们的理解，您请求的内容是：** 【一句话复述，例如：「获取我们持有的与您账户关联的全部个人信息副本，以及我们与之共享的第三方类别，并在提供副本后删除您的账户。」】

**接下来的安排：**
- 我们的实质回复目标日期为【日期——不晚于法定期限；内部时限更严的按内部时限】。【如身份验证未完成：「我们需要【具体验证步骤】才能继续，详见下文。」】
- 如因请求复杂或您同时提出了其他请求而需要更多时间，我们将在初始期限前告知您并说明原因。【制度允许延期的，引用相关条款。】
- 本请求不收费。【或：仅在制度允许且请求明显无依据或过度时收费——引用相关条款。】

【如身份验证未完成：】
**为验证您的身份，**请【具体验证步骤，例如：使用档案中的邮箱回复本邮件，并附上我们档案中记录的支付方式的后4位】。这不影响我们的处理期限，我们会同步推进。

如有疑问，请联系【隐私联系人】。

【发件人】
```

### 实质回复函：查阅请求

```markdown
主题：您的个人信息查阅请求 — 【公司】 — 【日期】

我们于【日期】收到您获取我们所持有的您的个人信息副本的请求。

**我们查找到的数据：**

我们持有与【标识符】关联的以下类别个人信息：

| 类别 | 来源 | 目的 | 保留至 |
|---|---|---|---|
| 【账户信息：姓名、邮箱】 | 您，注册时 | 账户管理 | 账户删除时 |
| 【使用数据】 | 我们的服务 | 数据分析、产品改进 | 【期间】 |
| 【客服往来记录】 | 您 | 客户服务 | 【期间】 |

**您的数据见附件**【格式】。【安全交付说明：密码保护的压缩包、有有效期的安全链接等。】

**第三方：**我们与以下处理者共享数据：【列表或处理者页面链接】。

**您的其他权利：**您还可以请求【删除 / 更正 / 复制】，方式为【方式】。

**未包含的数据：**
- 【类别】——【豁免及理由，例如「内部安全日志——披露将危及安全措施」】
- 【客服往来记录中关于其他个人的数据已删去】

如对本回复有疑问，请联系【隐私联系人】。
```

### 实质回复函：删除请求

```markdown
主题：您的个人信息删除请求 — 【公司】 — 【日期】

我们于【日期】收到您删除我们所持有的您的个人信息的请求。

**已删除：**

| 类别 | 系统 | 删除日期 |
|---|---|---|
| 【账户和个人资料】 | 生产环境 | 【日期】 |
| 【分析事件】 | 【数据分析平台】 | 【日期】 |
| 【等】 | | |

**保留的内容及原因：**

| 类别 | 原因 | 保留至 |
|---|---|---|
| 【交易记录】 | 法定义务（税务记录保留，【引用法律】） | 【日期】 |
| 【备份快照】 | 将在下一次循环时删除 | 【日期】 |

**受托处理者 / 第三方：**我们已要求【列表】从其系统中删除您的数据。

您的账户现已关闭。如对本回复有疑问，请联系【隐私联系人】。
```

## 法律依据

- 《个人信息保护法》第44条（知情权、决定权）、第45条（查阅、复制）、第46条（更正、补充）、第47条（删除）、第48条（解释说明）；第44-50条为个人权利的整体框架
