把尽职调查从一次性问答变成可持续推进的项目档案：原始底稿可追溯，整理后的文本可复用，事实查明可以增量更新，风险条线持续积累，法律研究可核验，输出文件可直接交付。

## 适用情形

- 并购、融资、上市、合规等项目的法律尽职调查。

## 办理步骤

### 阶段 1：项目立项

新项目开始时，先建立或补齐项目基本信息。

**项目画像**（至少包含）：

- 项目名称、委托人或目标公司
- 事项类型（并购 / 融资 / 上市 / 合规 / 其他）
- 交易类型、行业、法域
- 业务模式、特殊场景（数据合规 / AI 合规 / 国企合规等）
- 预期交付物、保密要求

**初始文件**：项目画像、工作日志、材料索引。

### 阶段 2：确定尽调清单

根据项目画像组合尽调清单：

1. **通用尽调清单**：所有项目都适用的基准检查项；
2. **行业专项清单**：按目标公司行业（制造 / 房地产 / 金融 / 科技 / 医疗等）；
3. **交易类型清单**：按交易性质（股权收购 / 资产收购 / 合并 / 少数股权投资等）；
4. **特殊场景清单**：数据合规、AI 合规、国企合规、环保合规、劳动用工等。

组合结果记入项目风险清单，作为后续事实查明的导航框架。

### 阶段 3：底稿接收与整理

收到文件、文件夹或链接后：

1. **识别文件性质**：合同、证照、审批文件、财务报表、诉讼材料、知识产权证书等；
2. **判断事实价值**：是否纳入正式底稿；
3. **分类归档**：按文件类型和涉及主体分类；
4. **转成可检索文本**：扫描件、图片、非标准格式转为结构化文本；
5. **更新索引**：同步更新材料索引和底稿清单。

### 阶段 4：事实查明与证据映射

围绕底稿和风险清单，持续维护以下文件：

| 文件 | 内容 | 规则 |
|---|---|---|
| 事实登记册 | 跨条线的核心事实，每条含事实编号、表述、支持材料、可信度、影响的风险点 | 新材料进来必须校准既有事实，不能只做摘要 |
| 证据映射 | 每个核查事项对应的事实依据、底稿依据、法规依据 | 没有证据链的内容只能列为待核实事项 |
| 矛盾日志 | 材料之间、材料与访谈之间、事实与法律判断之间的冲突 | 冲突不得被抹平 |
| 未决事实 | 待核实、待补充材料或待访谈确认的事实 | 持续跟踪直至关闭 |

**证据链格式**（每个风险或法律结论都应能拆成）：

```text
风险编号 → 核查事项 → 初步结论 → 事实依据 → 底稿依据 →
法规依据 → 相反证据 → 证据缺口 → 风险判断 → 整改建议 → 复核状态
```

### 阶段 5：问题条线推进

按行业、交易类型和风险清单建立若干问题条线，每条对应一个独立的法律 / 合规维度，如股权结构与历史沿革、重大合同、知识产权、劳动用工、税务、环境、数据合规。

**条线来源**：通用清单重点风险；行业清单重点风险；交易类型清单重点风险；委托人特别关注的事项；新底稿暴露的重大风险。

**每条线的文件结构**：

```text
条线文件夹/
  facts.md               ← 已查明事实
  materials.md           ← 相关材料索引
  legal_research.md      ← 法律研究结果
  risk_analysis.md       ← 风险分析
  gap_list.md            ← 证据缺口
  interview_questions.md ← 访谈问题
  supplement_request.md  ← 补充材料要求
  report_section.md      ← 报告章节草稿
```

条线不是越多越好，每条线都应对应事实查明和报告章节。

### 阶段 6：交付

**输出原则上由各问题条线汇总而来，不从零重写。**

默认交付物：

1. **尽职调查报告**：每个板块按「调查事实描述 → 法律评价分析 → 意见或建议」三段式组织；
2. **补充材料清单**：未取得的底稿、待补充的文件；
3. **访谈清单**：需向管理层或业务部门核实的问题；
4. **整改清单**：已发现的合规缺陷及建议整改方案；
5. **底稿目录**：全部已审阅材料的索引；
6. **内部未决问题清单**：律师团队内部待讨论事项。

## 报告写作

### 体例

```
目录 → 释义 → 引言 → 摘要 → 正文 → 附件
```

- **引言**至少包括：尽调目的、调查工作情况、特别提示（前提假设）、免责声明。
- **正文**按尽调内容分为若干板块，每板块三段：
  1. **调查事实描述**：只描述事实，不作法律评价；
  2. **法律评价分析**：对尽调结果进行法律分析并作出评价；
  3. **意见或建议**：给出预防、减轻、规避风险的确定性意见或参考性建议。
- **即使某事项不存在法律风险，也要给出明确评价**，避免读者疑问「到底有没有风险」。

### 风险揭示分级

- **可解决或可降低的风险**：提出具体方案；
- **无法完全避免、但不影响交易目的的风险**：作出提示即可，不过度强调；
- **可能影响交易目的实现的重大风险**：充分说明，并给出防范建议。

### 以委托人为中心

先呈现事实，再列举法律，最后给出评价：

```
小前提（法律事实）→ 大前提（法律规定）→ 结论（法律评价 + 风险提示 + 防范建议）
```

## 检查清单

**内部版与对外版分开。**

- **内部工作底稿**：可以包含整理说明、待核实事项、内部判断过程；
- **对外发送版本**：不得包含工具日志、内部过程语言、未经复核的推断。

**输出前检查：**

- [ ] 每个重大风险是否有底稿依据
- [ ] 每个法律结论是否有法规或权威来源
- [ ] 是否列明证据缺口
- [ ] 是否区分事实、法律、推理和建议
- [ ] 是否处理了新底稿带来的矛盾
- [ ] 是否去除了内部过程语言
- [ ] 是否符合委托人指定的格式
- [ ] 文件名是否清晰、可追溯

**依据不足时**，输出：

- 缺失的材料；
- 待访谈的问题；
- 暂不能形成结论的原因；
- 建议的补充路径。

**不得用流畅的文字掩盖证据不足。**
