诉讼和仲裁庭审准备的工作框架：建立案件档案，梳理事实和争议焦点，形成庭审提纲，完成庭前清单。原告、被告、仲裁员视角均可使用。

## 适用情形

- 诉讼或仲裁开庭前的准备。

## 需要准备的材料

- 起诉状 / 仲裁申请书、答辩状、证据目录等原始材料；
- 案情陈述；
- 程序信息（受理机构、案号、受理日期、程序阶段）。

材料不完整的，标明缺口，不猜测补充。

## 办理步骤

### 1. 建立案件档案

每个案件单独建文件夹，全程隔离：

```
【案件简称】/
├── input/          ← 原始材料（起诉状 / 申请书、答辩状、证据目录等）
├── scratch/        ← 中间成果（分析笔记、法律检索记录、草稿）
└── output/         ← 最终交付物（庭审提纲、争议焦点归纳等）
```

**案件简称**按以下优先顺序确定：

1. 委托人提供的案件名称；
2. 案号；
3. 当事人 + 案由（如「A 公司诉 B 公司买卖合同纠纷」）。

**原始材料只读**：存入 input 后不在其中修改。

### 2. 收集材料

- 口头描述的案情，整理成结构化摘要；
- 收到的文件存入 input；
- 不完整的材料标明缺口。

### 3. 案件分析

1. **基础信息**：当事人、诉讼 / 仲裁请求、案由、管辖依据、程序阶段；
2. **时间线**：按时间顺序组织事实；
3. **法律问题识别**：归纳本案涉及的法律问题和争议焦点；
4. **法律检索**：按《法律检索的来源顺序与标注》检索法律依据、类案和实务观点；
5. **补充检索**：知识库不足的，用法律数据库补充；
6. 分析记录存入 scratch。

### 4. 形成庭审提纲

无特别要求时，包含下文「庭审提纲」五个模块。

### 5. 完成庭前清单

见下文「检查清单」。

## 庭审提纲

### 1. 案件概览

- 当事人信息；
- 诉讼 / 仲裁请求摘要；
- 程序信息（受理机构、案号、受理日期、程序阶段）。

### 2. 争议焦点归纳

- 逐项列出核心争议点；
- 每个争议点附：各方主张、关键证据、可能适用的法律。

### 3. 事实查明提纲

- 需要查明的事实清单；
- 对应的证据编号和待确认事项；
- 标明已确认事实 / 争议事实 / 待查事实。

### 4. 法律适用提纲

- 各争议焦点涉及的法律依据（附具体条文编号）；
- 关键法条摘录；
- 类案裁判倾向（如有）；
- 举证责任分配分析。

### 5. 庭审发问提纲

- 按争议焦点分组；
- 针对各方当事人的发问清单；
- 每个问题的发问目的（要证明什么事实）。

## 证据状况标注

| 标记 | 含义 |
|---|---|
| ✅ | 事实可证明，证据充分 |
| ⚠️ | 事实有证据，但证明力待评估 |
| ❌ | 有事实主张，但缺乏证据 |
| 🔍 | 需通过申请调取、鉴定、证人等方式补强 |

## 检查清单

```
□ 事实时间线整理完毕
□ 证据清单及举证顺序确定
□ 对方可能的抗辩及应对预案
□ 关键法律依据标注（含具体条文）
□ 庭审发问问题清单
□ 鉴定 / 调查取证 / 追加当事人等申请是否已提交
□ 模拟庭审要点记录（如有条件）
```

## 不同角色的侧重点

| 角色 | 侧重点 |
|---|---|
| **原告 / 申请人方** | 证明请求权构成要件、组织进攻性证据、准备对方抗辩的应对 |
| **被告 / 被申请人方** | 否定构成要件、组织防守性证据、寻找程序抗辩（管辖 / 时效 / 主体） |
| **仲裁员 / 法官** | 兼顾双方观点，关注证据采信和法律适用，服务于庭审主持 |
| **代理律师** | 最强法律主张 + 最稳妥实务路径双轨分析 |

## 案件隔离

1. **严格隔离**：不同案件的材料、分析、输出互不混入；
2. **新案确认**：提到新案件时，先确认是继续讨论旧案还是新开一案；
3. **路径定位**：开始工作时先确认当前案件的文件夹，后续操作都在该文件夹内进行；
4. **跨案引用**：不引用其他案件的分析结论，除非委托人或主办律师明确要求。
