产品经理在即时通讯里问的「快速法务问题」，大多属于三种之一：(a) 不是问题，快速告知；(b) 确实需要认真审查，转交处理；(c) 看起来没问题但有陷阱，要把陷阱找出来。本流程对照公司风险校准表，在一分钟内完成分流。

目标是速度。产品经理下午 4:47 提问，要的是答案，不是备忘录。

## 适用情形

- 「这有问题吗？」「我们能做 X 吗？」「这个需要法务审查吗？」
- 需要即时给出「没问题 / 需要审查 / 暂停」判断的问题。

**不适用：**

- 问题实际上很复杂（多个议题、全新领域）：转上线审查或功能专项风险评估。
- 「帮忙审一下这份 PRD」：那是上线审查，不是分流。
- 拿不准：直接说「我不确定，正式查一下再回复」。错误的快速答案比慢一点的正确答案更糟。

## 需要准备的材料

- 公司风险校准表（通常仅告知 / 通常需付出工作量 / 通常阻断上线三类模式及时限）。
- 问题本身及必要的事实。

## 办理步骤

### 1. 确认答复发往何处

答复要发到频道、分发列表、对方、「所有人」的，先确认是否在保密范围内。公共频道、全公司列表、对方或对方律师、供应商和客户都会导致保密保护丧失。目的地在保密范围以外的，提供 (a) 仅供法务的保密版本，(b) 适合更大范围的净化版本，或 (c) 两者都给。不要加上保密抬头后又发到抬头保护不了的地方。

### 2. 对照校准表匹配

| 匹配结果 | 答复 |
|---|---|
| 「通常仅告知」 | 一句话告知：「没问题——【模式】。可以上线。」 |
| 「通常需付出工作量」 | 说明需要什么工作：「需要【个人信息保护影响评估 / 供应商审查 / 宣传检查】，约【表中时限】。需要现在启动吗？」 |
| 「通常阻断上线」 | 叫停：「暂停——【模式】。在任何人承诺日期前需要认真审查，约个时间谈。」 |
| 不匹配任何模式 | 明说：「这和以往的模式都不匹配，需要人工审查。」 |

### 3. 陷阱检查

有些问题表面没问题，实际有陷阱。识别事实模式，问一个能抓住陷阱的问题，再针对具体事实检索适用规则，然后判断是否构成问题。

| 问题听起来像 | 为什么可能不简单 | 用这个问题抓住 |
|---|---|---|
| 「能接入【供应商】吗？」 | 供应商接触新的数据类别，可能涉及个人信息保护和供应商风险制度，转研究 | 「哪些数据会流向他们？」 |
| 「能对定价页做 A/B 测试吗？」 | 按人群差异化定价可能涉及消费者保护和歧视相关制度，转研究 | 「两个版本看到的价格一样吗？用户怎么分到不同版本？」 |
| 「能给用户自动开通新功能吗？」 | 对之前已选择退出的用户默认开启，可能涉及同意和消费者保护规则，转研究 | 「这尊重了用户已有的偏好设置吗？」 |
| 「能在网站上用客户的 logo 吗？」 | 使用 logo 需要合同关系以外的单独授权，可能涉及名称、标识使用授权规则和客户合同条款 | 「合同对公开宣传怎么约定？有书面授权吗？」 |
| 「能拿这些数据训练模型吗？」 | 原始收集目的的使用权可能不包括模型训练，需查收集时向用户作出的告知和取得的同意 | 「收集时告诉了用户什么？用户在哪些法域？」 |
| 「这只是个内部工具」 | 内部工具也处理个人信息，可能涉及个人信息保护制度，转研究 | 「它处理谁的数据？员工、客户还是第三方？」 |
| 「我们做过类似的」 | 「类似」二字背后差别很大，差异处往往就是问题所在 | 「怎么类似？实际有什么不同？」 |
| 「能用【AI 供应商 / 大模型】吗？」 | 供应商 AI 条款可能允许用输入数据训练；用例可能需要算法备案，转 AI 用例分流 | 「有 AI 附录吗？哪些数据会输入模型？」 |
| 「能给这个功能加上 AI 吗？」 | 可能是 AI 登记册里没有的新用例，可能触发算法备案要求，转 AI 用例分流 | 「AI 做什么——辅助还是自动决定？作用于谁？」 |
| 「让模型自动决定就行」 | 无人工介入的自动化决策在某些法域受监管，需检索受影响用户所在法域的规则 | 「谁受影响？流程中有人工吗？受影响用户在哪里？」 |
| 「这是 AI 生成的内容」 | 输出的知识产权和披露义务因法域和供应商条款而异，转研究 | 「什么类型的内容？供应商条款对输出归属怎么约定？受众是谁？」 |
| 「只是用自己的数据微调」 | 训练数据权利、输出知识产权和供应商义务都会变，转 AI 供应商审查 | 「训练数据里有什么？有没有客户或员工的数据？」 |

只问一个问题，不要甩出整张检查表。答案显示确有问题的，标记并转研究；不能仅凭问题的措辞就得出法律结论。

### 4. 答复

一分钟内答复：✅ 没问题 / ⚠️ 需要审查 / 🛑 暂停，一句话说明理由。⚠️ 或 🛑 的，写明下一步。

## 答复格式

即时消息里的分流答复属于内部法律意见。答复要贴到与大量非法务人员共享的工单、文档或频道的，加内部保密抬头（按经办人角色确定）。

私信回复产品经理的短格式：

```
【✅ 没问题 | ⚠️ 需要审查 | 🛑 暂停】

【一句话：判断及原因。】

【⚠️：审查涉及什么，需要多长时间】
【🛑：和谁谈，什么时候谈】
```

示例：

```
✅ 没问题——只要隐私政策现有类别涵盖，新增一个分析事件属于告知即可。这个是涵盖的。
```

```
⚠️ 需要个人信息保护影响评估——【类别】新增数据收集。通常需要一天。需要现在启动吗？
```

```
🛑 暂停——「拿客户数据训练模型」涉及多个问题。客户协议对数据使用怎么约定？在任何人向客户承诺之前，先把协议调出来。
```

```
⚠️ 需要 AI 治理分流——在这个流程里加入大模型，要对照登记册检查用例，并确认上线前已完成算法备案。需要一天。现在开始吗？
```

## 语气

快速、直接、有用。产品经理不是来听课的。没问题就说「没问题」，不要列出查过的七件事；有问题就说什么有问题、怎么解决。做业务愿意来问的律师，不做他们想绕开的律师。

答复后可附下一步选项（起草某文件、上报、补充事实、观察等待、其他），由律师选择。
