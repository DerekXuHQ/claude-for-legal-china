用于中国法院类案检索、指导性案例或参考案例比较、裁判分歧分析。只核对案号格式的，见「法源与版本核验」。

## 需要准备的材料

- 研究争点、法律关系、地域、审级、事实时点、拟用论点。
- 敏感案件事实先在本地抽象成检索词；未经授权，不把案卷或身份信息提交给外部数据库或在线服务。

## 办理步骤

1. **检索**：用精确争点、法条、案由、法院、关键词及反向词检索；区分人民法院案例库、原始裁判文书、商业数据库和评论文章。记录检索式、日期、结果数及排除理由。
2. **逐案核对**：拟引用的案例读取可得全文，核对案号、法院、审级、生效/再审状态、关键事实、争点、裁判理由和不利段落。只有摘要的案例标为"线索"。
3. **比较**：比较共同要件事实、关键差异、程序差异、规范版本差异、对本案有利/不利之处。不得只因关键词相同就认定为类案。
4. **出案例矩阵**（格式见下），并列出相反案例或检索缺口。
5. **控制结论强度**：生效状态、全文或规范时点未能确认的案例，不写成确定的裁判趋势，保留人工复核事项。

## 文书结构

```
| 案例编号 | 来源与定位 | 身份及状态 | 事实/争点 | 规则与引用方式 | 可比性 | 不利内容 | 核验状态 |
|---|---|---|---|---|---|---|---|
```

## 检查清单

逐一检查下列十二个模块，重点展开时间、请求与要件、法源与解释、证明、程序和人工复核；其他模块也要记录适用情况、不适用理由或阻塞缺口。

| 模块 | 关注内容 |
|---|---|
| 任务背景 | 任务目的、用途、委托人 |
| 法域与地域 | 适用法律、地区、法院层级 |
| 时间 | 事实发生日、分析截至日、规范版本时点 |
| 主体 | 当事人、角色、代表谁 |
| 事项 | 案件或事务本身 |
| 请求与要件 | 请求权/抗辩及其构成要件 |
| 法源与解释 | 规范、效力层级、解释与适用 |
| 证明 | 证据、待证事实、举证责任 |
| 程序 | 程序路径、期限 |
| 结果与执行 | 可能结果、可执行性 |
| 策略与不确定性 | 策略选择、风险、未决问题 |
| 治理 | 授权、保密、人工复核 |
