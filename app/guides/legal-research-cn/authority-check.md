核验中国法法条、司法解释、规范性文件或案例的原文、版本、效力和引用方式。一般的文书润色不需要走这一流程。

## 需要准备的材料

- 待核的引用：法规名称、条号、案号或引用文字。
- 事实发生日、分析截至日、适用地域。
- 研究背景（代表谁、用途）尚不清楚的，先明确再核验。

## 办理步骤

1. **逐条提取**：每条待核引用的名称、发布机关、条号或案号、引用文字、事实发生日、分析截至日、适用地域。文本中的引用不默认为正确。
2. **找原文和版本记录**：先用公开官方来源查原文及发布、施行、修改、废止记录；有权限使用的商业法律数据库（如元典、北大法宝）可辅助发现和交叉定位，记录查询时间与结果编号。数据库摘要须回读全文。
3. **逐条比对**：比对引用文字与原文，核实效力层级、特别法关系、过渡条款和事实时点。案例另外核实裁判层级、是否生效、是否被再审或撤销、指导性/参考性身份及案情可比性。
4. **出核验表**（格式见下）。状态只用"已核验""部分核验""未核验""不适用"四种；数据库检索命中不等于已核验。
5. **原文不可得时**：核心条文或案例原文查不到的，说明失败的检索途径与时间、替代路径和受影响的结论；该结论不再作确定性表述。

## 文书结构

```
| 编号 | 待核表述 | 原始来源与定位 | 版本和适用时点 | 核验状态 | 差异 | 建议引用方式 |
|---|---|---|---|---|---|---|
```

## 检查清单

对本次任务逐项检查下列十二个模块：适用的，给出最低结论或待核动作；不适用的，说明与本次核验范围有关的理由；受阻的，记录缺口与停止路径。简短核验可用一行状态表，不必扩张为全案意见。

| 模块 | 关注内容 |
|---|---|
| 任务背景 | 任务目的、用途、委托人 |
| 法域与地域 | 适用法律、地区、法院层级 |
| 时间 | 事实发生日、分析截至日、规范版本时点 |
| 主体 | 当事人、角色、代表谁 |
| 事项 | 案件或事务本身 |
| 请求与要件 | 请求权/抗辩及其构成要件 |
| 法源与解释 | 规范、效力层级、解释与适用 |
| 证明 | 证据、待证事实、举证责任 |
| 程序 | 程序路径、期限 |
| 结果与执行 | 可能结果、可执行性 |
| 策略与不确定性 | 策略选择、风险、未决问题 |
| 治理 | 授权、保密、人工复核 |
