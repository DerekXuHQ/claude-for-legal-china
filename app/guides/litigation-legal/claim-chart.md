把诉讼请求（或抗辩）的构成要件、或专利权利要求的技术特征，逐项映射到证据、被控侵权产品或现有技术，每个单元格附精确出处，并把缺口清单作为首要成果。用于起诉前审查、举证规划、庭审准备，以及专利侵权、无效分析和审查他人制作的对照表，回答"证明这项主张还缺什么"。

## 适用情形

| 类型 | 用途 |
|---|---|
| 专利权利要求对照表·侵权 | 权利要求要件 vs 被控侵权产品 |
| 专利权利要求对照表·无效 | 权利要求要件 vs 现有技术（专利法第22条新颖性/创造性） |
| 专利权利要求对照表·审查 | 审查他人制作的对照表 |
| 民事要件分析表 | 任何诉讼请求或抗辩的构成要件 vs 证据 |

## 定性声明（放在每份分析表顶部，不得删减）

> 本分析表是供律师分析和核实的草案，不是递交的主张、代理词、开庭陈述或法律意见。每个映射都是律师必须对照来源核实的调查线索。所列要件来自法律条文、司法解释或权利要求的解析——适用管辖地的**控制性**法律依据可能不同且始终优先。缺口检测是证据收集或诉讼动议的起点，不是对案件事实的法律结论。

宁多标、不漏标：漏标一个缺口的后果难以挽回——起诉时某个要件缺乏事实支撑、质证时某项主张没有证据、庭审时无法证明损害；多标一个缺口，律师审查时清除即可。

## 需要准备的材料

共同信息：
- **立场**：主张方还是抗辩方。
- **管辖地/法院**：省/直辖市和法院，适用法律和司法解释可能因地域不同。
- **阶段**：起诉前、举证、庭审、上诉。
- **既有分析表**：审查模式下必备。
- 案件立场、阶段、案件理论、诉状（起诉状/答辩状），使分析表跟踪实际主张的内容。

专利模式另需：专利号、至少一项主张的权利要求、说明书和审查历史、已有的权利要求解释裁定（如有）。

民事模式另需：诉讼请求或抗辩、证据材料。

## 办理步骤：专利权利要求对照表

### 1. 解析权利要求

把主张的独立权利要求解析为编号要件：

- **前序部分**：注明是否具有限定作用。
- **过渡词**："包括"（开放式）/"由……组成"（封闭式）。
- **要件**：按逗号/分号分隔，编号 `[1a]`、`[1b]`、`[1c]`。编号保持稳定，它是对照表的骨架。
- **功能性限定**（《专利审查指南》相关规定）：每个"用于【功能】的装置"，范围为说明书公开的结构加等同替代。
- **从属权利要求**：引用父权利要求，只分析附加技术特征。

解析结果先交律师确认再映射。解析错误会污染后面每一行。

### 2. 权利要求解释检查

标记争议术语：
- 说明书中定义或自创的术语；
- 审查历史中有修改、争辩或放弃的术语；
- 功能性语言（"配置为""适用于""可操作以"）；
- 相对术语（"大体上""约"），有清楚性风险。

对每个标记的术语，说明在哪种解释下映射成立、在哪种解释下不成立。

### 3. 映射

对每个要件、每个目标：

1. **找证据**：引证来源并精确定位。
2. **逐字引用**：一字不差，不转述。
3. **定映射类型**：

| 映射 | 含义 |
|---|---|
| 字面 | 权利要求语言直接覆盖被控特征/现有技术公开 |
| 等同 | 功能-方式-结果实质相同或非实质性差异（侵权模式） |
| 部分 | 部分要件存在 |
| 未找到 | 要件不存在 |
| 需要证据 | 现有材料无法判断 |
| 依赖于权利要求解释 | 取决于争议术语的解释 |

4. **每个单元格的状态**：已映射 / 已映射-等同 / 部分 / 未找到 / 需要证据 / 依赖于权利要求解释。

### 4. 从属权利要求逐项落表

每个主张的从属权利要求都要产出实际的分析行，不能只写"应予分析"之类的占位说明。

### 5. 间接侵权、共同侵权等

只标记、不发表意见：
- 间接侵权（教唆、帮助）；
- 共同侵权（《民法典》第1168条）；
- 故意侵权。

### 6. 无效门槛（仅无效模式）

- 新颖性（《专利法》第22条第2款）：全部技术特征在一份对比文件中公开。
- 创造性（《专利法》第22条第3款）：突出的实质性特点和显著的进步（发明）/ 实质性特点和进步（实用新型）。
- 清楚性（《专利法》第26条第3-4款）。
- 修改超范围（《专利法》第33条）。

## 办理步骤：民事要件分析表

### 1. 识别诉讼请求

- 什么诉讼请求或抗辩？多个的分别分析。
- 哪一方？原告的请求权基础，或被告的抗辩。
- 哪个管辖地？构成要件和法律依据因管辖地而异。
- 对照起诉状/答辩状，跟踪实际主张的内容。

### 2. 确定构成要件

- **从法律依据提取**：确定适用的法律条文或司法解释，解析为编号要件。
- **自定义**：由律师定义要件，或依据法条、司法解释、诉状内容解析。
- **抗辩事由**：诉讼时效、免责事由、过错相抵等抗辩要件同样适用。

映射前与律师确认要件列表和控制性法律依据（法条或司法解释）。管辖地有特定司法口径的（例如某省高院的指导意见），主动提出。

### 3. 映射

对每个要件：
- **支持证据**：什么证明这个要件，精确引用来源。
- **逐字引用**（证言或书面证据），不转述。
- **相反证据**：什么指向另一方向，同样引用。
- **强度**：强 / 中等 / 弱 / 无。
- **状态**：已支撑 / 部分 / 有争议 / 缺口 / 需要举证。

### 4. 缺口检测（核心成果）

映射完成后列出缺口：

> **证据薄弱或无证据的要件：**【列表】
>
> - 主张方：这些缺口可能影响诉讼请求能否成立。
> - 抗辩方：这些是突破点——请求方须证明每个要件，一个缺口就是一项抗辩。
> - 举证阶段：这些是优先举证方向。

### 5. 按阶段使用

- **起诉前**：每个要件是否都有足够事实支撑，使主张具有合理性？
- **举证阶段**：每个"缺口"或"需要举证"的要件需要什么证据？
- **庭审准备**：举证顺序、何种证据证明哪个要件、由谁举证。

## 文书结构（两种模式通用）

每份输出顶部放定性声明。每个诉讼请求/抗辩/专利权利要求，对每个目标各一张表：

```markdown
| 【#】 | 要件（逐字） | 证据支撑（精确引用） | 相反证据 | 强度 | 状态 | 已核实 |
|---|---|---|---|---|---|---|
| 1 | 合同成立 | 【证据3，合同第1条】 | 无 | 强 | 已支撑 | ☐ |
| 2 | 原告履行 | 【陈述第4-9段】 | 【质证意见】 | 中 | 有争议 | ☐ |
```

表后依次附：
- **缺口列表**（优先）；专利模式为"需要证据"列表；
- 最强要件、最弱要件小结；
- 结论行：不下结论，只列明"已支撑的要件：【列表】；需要证据/处于缺口状态的要件：【列表】"。

需要表格文件的，另存两份 CSV（或 Excel）：一份存值，一份存逐字引用、精确出处和备注。导出电子表格时，以 `=`、`+`、`-`、`@`、制表符、回车符开头的单元格值前加单引号，防止被当作公式执行。

文件命名建议：
- 专利侵权：`claim-chart-infringement-【专利号】-claim【#】-【目标】-YYYY-MM-DD`
- 民事：`element-chart-【请求简称】-【立场】-YYYY-MM-DD`

成稿后附摘要：主张、目标、管辖、阶段、按状态统计的要件数、缺口列表，并提示每个单元格都是调查线索。

## 常见风险

- **下结论**：分析表不认定侵权、不侵权或责任成立。
- **替律师定解释**：不决定权利要求解释（专利）或控制性构成要件（民事），只标记争议术语/基准要件并在声明的假设下分析。
- **替代专业分析**：技术专家、损害赔偿专家的工作是独立成果，分析表只引向它们。
- **当作定稿递交**：每份输出都是草案，不递交、不签署。
- **推测填格**：没有证据的单元格就是"需要证据"或"缺口"，不得猜测。

## 法律依据

- 《中华人民共和国民法典》第1168条
