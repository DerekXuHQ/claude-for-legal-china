案件结果是整个案件组合里最有价值的数据，能用来校准今后案件的风险判断。结案时要把结果结构化地记录下来，让记录日后有用，而不只是归档。

## 适用情形

- 案件以和解、撤诉、判决、撤回、合并等方式结束，需要结案。

## 需要准备的材料

- 案件台账中该案的记录。
- 案件登记表（立案时的预判）。
- 案件历史记录。
- 和解协议、终局裁判文书、撤诉裁定等（如有）。

## 办理步骤

1. **确认案件已登记。** 台账中找不到该案件的，先核对代号；确实从未登记的，没有可结的记录。
2. 确认案件代号和当前状态。
3. 按下文「结案内容」逐项记录。
4. **结案前须经律师审查。** 结案会终止主动跟踪，可能影响相关的证据保全（需要的，另行解除保全），并形成单位依赖的最终记录。由非律师人员办理结案的，应先与律师审查；为此可准备一页摘要：案件、结案类型和条款、最终成本与初始预判对比、计提准确性、关联案件或上诉是否仍在进行、提前结案可能出错的地方、需要问律师的问题。需要找律师的，可联系当地律师协会或拨打 12348 法律援助热线。未经确认，不更新结案信息。
5. 写入前把完整的结案记录和台账变更给承办人确认。
6. 更新台账、追加历史记录、在登记表末尾加结案块（格式见下文）。

## 结案内容

### 1. 结案类型

| 类型 | 需记录 |
|---|---|
| 和解 | 金额、结构性条款 |
| 撤诉 | 对方撤诉或我方撤诉 |
| 判决我方胜诉 | 在哪个阶段、上诉风险 |
| 判决我方败诉 | 在哪个阶段、上诉状态、敞口已确定 |
| 撤回 | 由对方撤回，附情况说明 |
| 合并 | 并入其他案件（写明主案代号） |
| 其他 | 附说明 |

### 2. 结案日期

案件实际结束的日期（和解协议签署、裁判文书下达、撤诉裁定作出）。

### 3. 最终成本

- 公司实际成本：和解金额 + 律师费 + 禁令或结构性成本。
- 与立案时初始敞口范围的对比：当初预判是否准确。
- 计提准确性（如有计提）：账面金额与实际金额。

### 4. 经验教训

两三句话：哪些判断对了，哪些错了，立案时本应更早发现什么。这是今后的律师会反复翻看的部分，要坦诚。「低估了败诉可能性——对方比预期更激进」比「结果对我方有利」有价值得多。承办人不愿填写的，留空，不代为总结。

### 5. 关联文件

和解协议、终局裁判文书、撤诉裁定等的存放位置。非必填。

## 记录格式

### 台账字段更新

```yaml
status: 已结案
closed: 【日期】
outcome: 【结案类型】
final_cost: 【金额】
last_updated: 【当日】
```

保留原有全部字段，不删除台账记录。

### 历史记录追加条目

```markdown
## 【日期】—— 案件结案：【结案类型】

**结果：**【经过与条件】
**最终成本：**【金额，以及结构性条款（如有）】
**与初始预判对比：**【对照登记表中的范围】
**计提准确性：**【如适用】

**经验教训：**
【2—3 句坦诚的回顾】

**关联文件：**【和解协议 / 终局裁判文书等（如有）】
```

### 登记表末尾的结案块

只在末尾追加，不修改前面各节（它们是立案时的历史记录）：

```markdown
---

## 结案于【日期】

【结果摘要，一段，详见历史记录中的结案条目】
```

## 注意事项

- **不删除案件。** 已结案件保留在台账和档案中，是积累案件判断经验的依据。
- **不重新激活已结案件。** 已结案件又出现（上诉、关联诉讼）的，开新案，并在新案登记表中引用已结案件。
