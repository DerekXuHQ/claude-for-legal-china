就中国法问题形成可追溯的咨询分析、客户答复或正式法律意见草稿。只需核对一条法规原文的，按法源核验的方法办理即可。

## 适用情形

- 客户提出法律咨询，需要书面分析或答复。
- 需要起草正式法律意见。

## 需要准备的材料

- 咨询问题原文。
- 服务对象、利益冲突审查状态。
- 事实发生日、所问法律关系、交付深度和用途。
- 客户提供的事实材料。

已有项目目录的，按项目约定存放底稿，不迁移原件；尚无目录且需要保存底稿的，再新建目录。

## 办理步骤

### 1. 拆解问题

把以下内容分开：

- 原始问题；
- 客户真正要决定的事项；
- 已知事实；
- 待核实的事实。

复杂问题拆成有先后依赖关系的子问题。发现紧迫期限的，先标出来；尚无送达或知悉证据的，不作确定计算。

### 2. 研究

- 关键规范：核对原文、版本和适用时点。
- 类案：按类案比较的方法处理。
- 检索摘要和凭记忆得到的内容只作线索，不作依据。
- 记录查询式、使用的检索工具、来源定位、检索失败和未覆盖的事项。

### 3. 选择成果形式并起草

按使用场景选择：简答、单问题分析、综合咨询，或正式法律意见草稿。正文按以下顺序展开：

1. 条件化结论；
2. 已知事实 / 待证事实；
3. 法律依据；
4. 相反解释；
5. 风险；
6. 可行动方案；
7. 待确认事项。

不得把客户的叙述直接写成已查明的事实。

### 4. 交付前自检

正式交付前，检查来源覆盖、时效、程序、期限和证据。关键依据无法取得的，停止相应的确定性结论，交律师复核。未经授权不对外发送客户材料或答复。

## 检查清单

逐项检查以下维度：适用的写出最低限度的结论；不适用的写明本案为何不适用；受阻的列出缺口和停止路径。

| 维度 | 检查内容 |
|---|---|
| 任务背景 | 服务对象、客户要决定的事项、用途、交付深度 |
| 管辖 | 适用的法域和地区 |
| 时点 | 事实发生日及应适用的规范版本 |
| 主体 | 各方当事人及其关系 |
| 事项 | 所问的法律关系 |
| 请求与构成要件 | 相关主张及其要件 |
| 法律依据与解释 | 规范原文、版本、适用时点和相反解释 |
| 证据 | 已知事实的依据、待证事实 |
| 程序 | 相关程序和期限 |
| 结果与执行 | 可能的结果及其执行 |
| 策略与不确定性 | 可行动方案、风险、待确认事项 |
| 治理 | 利益冲突、授权、保密和对外发送的边界 |

## 常见风险

- 把客户叙述当作事实。
- 引用的规范未核对版本和适用时点。
- 用检索摘要或记忆代替原文。
- 没有送达或知悉证据就计算期限。
- 结论不附条件，未写相反解释。
- 未经授权对外发送答复。
