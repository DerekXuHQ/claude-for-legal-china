# AI 问答的设计

目标：AI 像一个能干的律师助理那样工作，不是把资料摘要一下就交差。先弄清是什么事、缺什么事实，再按这类事的专业方法检索和分析，给出能直接用的结论、依据和下一步。

调研依据见 `docs/legal-ai-research.md`（国内外法律 AI 产品的做法、公开评测、官方查询的可行性）。

## 一次问答怎么走

```
用户提问（可附文件）
  → ① 分流：判断任务类型、地区、已知事实、缺哪些关键信息
  → ② 追问：缺关键事实时先问（3–6 个问题，可以跳过，按现有信息先给初步判断）
  → ③ 按任务的工作方法检索和分析（任务手册 + 本地资料库工具）
     · 合同审查、方案审查走专门的多轮流程（见下）
  → ④ 核对引用：答案里出现的每个法条都回资料库核对；查不到的标出来
  → ⑤ 输出：结论先行 → 依据 → 分析 → 下一步 → 需补充的材料 → 何时找律师
```

## 任务类型

每类任务有一份**任务手册**（`server/ai/tasks/<id>.md`）：什么请求归这类、必问信息、工作步骤、必查依据和检索顺序、地区差异、输出结构、常见错误。分流时 AI 读所有手册的「适用情形」，回答时只加载对应的那一份。

| 编号 | 任务 | 典型问题 |
|---|---|---|
| employment | 劳动用工 | 辞退要赔多少、员工要 N+1 合不合理、试用期、加班费、竞业限制 |
| contract_review | 合同审查 | 帮我看这份合同有没有漏洞 |
| plan_review | 方案合规审查 | 这个营销活动 / 商业模式有没有违法的地方 |
| legality | 合法性判断 | 这样做违法吗、他这样做违法了我怎么办 |
| dispute_defense | 被诉、被索赔应对 | 收到起诉状 / 仲裁申请 / 律师函 / 处罚告知书 |
| claim_feasibility | 起诉、追款可行性 | 我能不能告他、有没有依据、值不值得 |
| deadline | 期限与时效 | 还能不能起诉、上诉期还剩几天 |
| entity_check | 主体调查 | 这家公司靠不靠谱、什么背景 |
| corporate | 公司治理与股权 | 出资、股权转让、决议、法定代表人 |
| drafting | 文书起草 | 律师函、催款函、解除通知、规章制度、决议 |
| data_compliance | 数据与网络合规 | 个人信息、隐私政策、数据出境、ICP、等保、算法备案 |
| ip | 知识产权 | 商标能不能注册、是否侵权、怎么维权 |
| admin_enforcement | 行政监管应对 | 行政检查、处罚、听证、复议 |
| consumer | 消费者纠纷 | 退款、三倍 / 十倍赔偿、职业索赔 |
| regulation_lookup | 法规检索与解读 | 最新规定是什么、新法对我有什么影响 |
| case_research | 类案与裁判倾向 | 同类案件一般怎么判 |
| criminal_risk | 刑事风险筛查 | 这样做会不会构成犯罪 |
| general | 其他法律咨询 | 不属于以上的 |

## 合同审查流程（多轮）

调研显示，AI 在文档问答上已经超过律师，但修改合同条款仍明显不如律师。所以合同审查拆成几轮，并且用另一家的模型交叉复核：

1. **合同画像**（主力模型，低推理）：合同类型、双方、我方身份、交易背景、关键商业条款；对照该类型的必备条款清单，找缺失条款。
2. **逐段审查**（主力模型，中推理，分段并行）：每段逐条看合法性与效力 → 权利义务是否平衡 → 能否执行 → 商业风险 → 表述歧义。每个问题给：原文、问题、风险等级（高 / 中 / 低）、首选修改文本、后备修改文本、谈判理由、法律依据。可以调用资料库检索工具。
3. **对抗式复核**（复核模型，另一家族，高推理）：对高、中风险问题逐个挑错（是否真的成立、依据对不对、修改是否过度），再通读全文找漏掉的问题。
4. **引用核对**：每条法律依据回资料库核对条文存在、现行有效；对不上的删掉并提示。
5. **汇总**（主力模型）：总体结论、最需要改的几处、谈判策略、审查意见表。

方案合规审查（plan_review）用同样的流程，把「条款」换成「方案环节」。

## 模型分工

| 角色 | 默认 | 用途 |
|---|---|---|
| 主力模型 | 输入框下方选的模型（默认 gpt-6-luna） | 分流、追问、检索分析、合同逐段审查、汇总 |
| 复核模型 | 设置里选；默认自动选另一家族的强模型 | 合同 / 方案审查的对抗式复核 |

推理强度：分流用低；检索分析按输入框的「快速 / 标准 / 深入」；合同逐段审查用中；复核用高。是否值得默认用更强的模型（如 gpt-6-astra），用评测集比较后再定，见下。

## 引用核对

- 资料库工具返回的条文都带编号，回答里用 `[[art:编号]]` 引用，点开就是原文。
- 回答写完后，再扫一遍正文里所有「《某法》第某条」：能在资料库对上的自动加链接；对不上的在后面标「（资料库未核实）」，不让编造的依据混在里面。

## 官方查询

工商登记、失信被执行人、商标近似检索、专利、ICP 备案等官方系统都有反爬、验证码或登录，不能在后台自动查，也不绕过。做法：AI 生成查询要素 → 一键打开官方页面 → 用户查完把结果贴回来 → AI 分析。统一社会信用代码的校验位在本地离线核对。网信办公布的算法和大模型备案名单是公开页面，可以直接收入资料库（后续）。

## 评测

`eval/cases.jsonl`：按高频任务写的真实场景题，每题带评分要点（必须识别的问题、必须引用的依据、必须追问的事实、不能出现的错误）。`scripts/eval.mjs` 用不同模型和推理强度跑一遍，再由另一个模型按评分要点打分，比较准确性、完整性、可用性和成本，据此决定默认配置。
